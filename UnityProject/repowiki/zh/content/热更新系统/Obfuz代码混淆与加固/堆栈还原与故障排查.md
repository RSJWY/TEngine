# 堆栈还原与故障排查

## DeobfuscateStackTrace

Obfuz 提供命令行工具，根据 mapping 将混淆类型和方法名替换回原始名称。

典型命令：

```bat
DeobfuscateStackTrace -m path/to/symbol-mapping.xml -i obfuscated.log -o deobfuscated.log -r
```

常用参数语义：

- `-m`：mapping 文件；
- `-i`：输入日志；
- `-o`：输出日志；
- `-r`：移除 Obfuz 生成的 dispatch、辅助方法等堆栈帧。

应保存原始日志和还原日志。`-r` 便于阅读，但可能移除定位 Pass 异常所需的生成帧。

## 日志归档要求

线上异常至少包含：

- App 主包版本、平台、渠道、架构；
- 资源包与热更新版本；
- mapping ID；
- Obfuz/HybridCLR 工具版本；
- 是否多态 DLL；
- 原始完整堆栈；
- native crash 地址和符号（如适用）。

服务端按 mapping ID 选择对应文件，不能永远使用“最新 mapping”。

## 构建故障

### mapping重复键

错误示例：

```text
ArgumentException: An item with same key has already been added
RenameRecordMap.LoadPropertyMapping
```

官方说明旧版本在多个同名带参 property（如 indexer）时可能生成冲突。处理：

1. 备份旧 mapping 和产物。
2. 升级 Obfuz。
3. 在允许重新分配符号的新主包边界删除/重建 mapping。
4. 不要覆盖仍用于旧版本日志解析的 mapping。

### IL2CPP找不到原始名称

若错误中出现未混淆的类型/字段/方法/property/event，优先检查报错程序集是否属于第 4 类但未配置。加入 `NonObfuscatedButReferencingObfuscatedAssemblies` 后重建。

### 混淆成功但IL2CPP失败

可能原因：

- Obfuz 生成非法 IL；
- IL2CPP 对某元数据名有隐式限制；
- 旧 mapping 强制复用不兼容名称；
- Pass 与当前 Unity/IL2CPP 版本不兼容。

诊断顺序：

1. 保存最小复现和原始/混淆 DLL。
2. 用验证器/反编译器检查 IL。
3. 仅在备份后尝试新 mapping。
4. 逐个禁用 Pass 定位。
5. 升级到匹配版本。
6. 向上游提交可复现工程。

### Assembly解析失败

检查：BuildTarget、搜索路径、同名 DLL、Editor-only 依赖、asmdef 平台过滤和包缓存版本。

## 兼容检测告警

`[ReflectionCompatibilityDetector]` 不是必然错误。处理流程：

1. 定位反射字符串来源。
2. 确认目标是否改名。
3. 选择保名、TypeMapper/Instinct 或稳定业务 ID。
4. 建立用例验证。
5. 只有确认误报后才记录豁免。

不要为了清空日志全局关闭检测。

## 运行时故障

### Obfuz.Runtime TypeLoadException

官方 FAQ 说明不要在原始源码和未混淆 `Obfuz.Runtime` 已加载的 Editor AppDomain 中直接执行混淆 DLL。应在 Player/隔离工程验证。

### `$Obfuz$RVA$`类型初始化异常

典型原因：对应 `EncryptionService<T>.Encryptor` 尚未设置。检查：

- VM 代码是否编译进 Player；
- secret bytes 是否正确加载；
- Scope 类型是否一致；
- 初始化是否早于任何静态构造器/入口；
- 热更新 DLL 与主包 VM/静态密钥版本是否匹配。

### 热更新入口找不到

检查 `GameApp` 类型和 `Entrance` 方法是否被保名、主逻辑 DLL 名是否正确、反射 BindingFlags 和程序集是否加载成功。

### UI资源找不到

检查 UI 派生类型名是否被改写、`typeof(T).Name` 是否作为 YooAsset 地址、`UIBase` 的 `ApplyToChildTypes` 是否生效。

### 多态DLL加载失败

检查：

- 主包是否执行扩展 GenerateAll；
- DLL structure secret 是否一致；
- 最终上传文件是否已转换；
- AOT metadata DLL 是否同样转换；
- 是否开启标准 DLL 禁载；
- CDN 是否混入旧主包产物。

## 二分定位Pass

推荐顺序：

1. 只启用 Symbol。
2. + RemoveConstField。
3. + Const。
4. + Expr。
5. + Call。
6. + ControlFlow。
7. 最后少量 FieldEncrypt。

每一步都用同一真机用例和配置快照。不要一次关闭多个 Pass 后直接判断根因。

## 发布前故障预防

- 自动检查默认 secret；
- 验证 VM、mapping、密钥和输出文件存在；
- 反射告警必须有处理记录；
- 构建后扫描最终 DLL 是否含预期混淆名；
- 启动全量 Scene/Prefab/ScriptableObject 冒烟；
- 运行热更新、AOT metadata、多态 DLL 和回滚测试；
- 用人工制造异常验证堆栈可还原。
