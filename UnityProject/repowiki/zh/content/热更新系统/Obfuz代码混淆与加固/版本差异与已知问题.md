# 版本差异与已知问题

## 基线差异

本专题核对：

- 文档 commit：`1dbb50301ecee9aee20c60dd1e5a2633bb1707d1`；
- 源码 commit：`fa2345017a22c74d13d9dd84b21bfc158d13b80d`；
- 源码 package version：`3.1.0`。

文档与源码不是同一发布日期，因此所有“已支持”描述都需以目标版本源码和实际产物验证。

## Eval Stack默认不运行

文档完整描述 Eval Stack Pass，配置和枚举也存在；但 `3.1.0` `ObfuscatorBuilder` 中：

```csharp
// if (obfuscationPasses.HasFlag(ObfuscationPassType.EvalStackObfus))
// {
//     builder.AddPass(new EvalStackObfusPass(...));
// }
```

因此默认 Settings 流程不会运行。Wiki 将其标为“实现存在、默认注册关闭”，不把它计入当前可用生产 Pass。

## 常量数组文档矛盾

`const-encryption.md` 前部列出简单类型数组和多维数组受支持；规则表的 `encryptArray` 又写“目前不支持常量数组加密，此配置无实际效果”。必须用 `3.1.0` 样本和源码确认，未验证前不要依赖数组加密保护。

## 文档复制错误

若干 Pass 文档把本节设置误写为“常量加密”或“函数调用”，例如 ControlFlow/EvalStack。应以类名和规则字段判断实际含义。

## 发布日志过时

官方 `releaselog.md` 只记录到：

- 2025-05-25 beta2；
- 2025-05-22 beta1；
- 2025-05-17 首个开源版本。

明显落后于源码 `3.1.0`。不能用该发布日志推断 3.x 的变更、兼容性或迁移要求，应查源码 commit/tag 和包说明。

## 命名拼写不一致

文档中存在多处历史拼写：

- `Referenceing`；
- `CallEncryptSettings` 与 `CallObfusSettings`；
- `Encrytion/Encryption`；
- `Sybmol/Symbol`；
- `Obfusaction/Obfuscation`。

配置序列化字段和当前源码 API 才是权威。复制文档代码前必须编译验证。

## Debug模式语义

官方描述 Debug Symbol 模式会忽略规则和正式 mapping 输入。不同版本是否完全忽略全部规则需实测；本 Wiki按官方语义记录，但不以 Debug 结果证明正式规则最终命名。

## 默认All风险

源码 `ObfuscationPassSettings.enabledPasses` 默认 `All`，本工程序列化为 `-1`。由于 EvalStack 未注册，`All` 实际表示“所有已注册 Pass”，不是文档列表的数学全集。

空规则下各 Pass 的默认策略不同：

- Symbol 倾向尽可能混淆；
- Const/Call 等可能覆盖大范围；
- Field Encrypt 官方文本强调默认不加密字段，但应以当前规则默认验证；
- ControlFlow 文档全局默认 `None`，与设置开启并不必然等于所有方法被处理。

不能只看 `enabledPasses` 判断最终范围。

## 本工程包来源不完整

当前扫描：

- `Packages/manifest.json` 仅显式包含 HybridCLR Git 依赖；
- 未找到 Obfuz/Obfuz4HybridCLR package 声明或源码文件；
- 但项目代码在 `ENABLE_OBFUZ` 下引用这些 API，且有 `ProjectSettings/Obfuz.asset`。

可能原因包括本地/嵌入包未提交、包在用户环境中注入、或仓库当前处于禁用宏状态。正式 CI 前必须明确包的可复现来源，否则开启宏会编译失败。

## 当前配置与产物不一致

[Obfuz.asset](file://ProjectSettings/Obfuz.asset) 配置了：

- VM 输出路径；
- 静态/动态密钥输出路径；
- mapping 路径；
- 多态 DLL 启用。

但实际检查：

```text
Assets/Obfuz                         不存在
Assets/Resources/Obfuz               不存在
Assets/Obfuz/SymbolObfus/mapping     不存在
```

这证明配置尚未完成生成流程。不能因为 asset 字段存在就认为功能生效。

## 默认Secret

当前值：

```text

Obfuz
obfuz-polymorphic-key

Watermark = Obfuscated by Obfuz
```

均不适合正式发布：已公开、可预测、无法区分项目或渠道。

## Build Pipeline与显式热更新混淆

`buildPipelineSettings.enable=0` 只表示 Unity Player 自动混淆关闭；`BuildDLLCommand` 仍可能在宏开启时显式混淆热更新 DLL。文档和发布流程必须区分这两条链，避免出现“主包 AOT 未混淆、热更新已混淆”或反向不一致而无人知晓。

## PDB兼容未证明

当前工程支持 dev PDB，但未证明 PDB 与混淆后 DLL 的映射关系。正式 release 已清理 PDB；若要调试混淆代码，应使用 mapping 或确认工具支持写出匹配 PDB。

## 升级检查表

每次升级 Obfuz/HybridCLR：

1. 对比 `ObfuscatorBuilder` Pass 注册与顺序。
2. 对比 `ObfuscationPassType` 和 Settings 序列化字段。
3. 检查旧 `Obfuz.asset` 是否发生字段迁移。
4. 检查 mapping 格式兼容。
5. 检查 Obfuz4HybridCLR 的版本矩阵和菜单/API 名称。
6. 重新运行 GenerateAll。
7. 重做 IL2CPP、热更新、反射、序列化、多态 DLL 回归。
8. 在新主包边界决定是否重建 VM/mapping。

## 维护结论

本专题把“官方声明”“`3.1.0` 源码事实”“当前 TEngine 工程状态”明确分开。后续升级时，应更新本页基线和差异，而不是无条件把旧结论沿用到新版本。
