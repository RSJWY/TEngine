# 增量混淆与版本管理

## 增量稳定性的来源

官方说明主要 Pass 使用确定性策略：

| Pass | 稳定机制 |
|---|---|
| Symbol | 复用 `symbol-mapping.xml` |
| Const | 基于目标与配置的确定性随机加密 |
| Field | 每字段确定性随机参数 |
| Call | 每调用目标确定性索引与随机参数 |

只要配置、输入和工具版本稳定，同一符号或对象应尽量得到稳定结果。这对热更新 diff、HybridCLR DHE 和线上堆栈还原非常重要。

## mapping生命周期

不要只维护一份不断覆盖的 mapping。推荐：

```text
BuildArtifacts/Obfuz/
  app-1.0.0/
    tool-versions.json
    Obfuz.asset.snapshot
    rules/
    symbol-mapping.xml
    dll-sha256.txt
  hotfix-1.0.1/
    base-app: 1.0.0
    symbol-mapping.xml
    dll-sha256.txt
```

当前活动 mapping 可留在 `Assets/Obfuz/...` 并纳入 Git；发布时复制不可变快照到制品库。

## 主包与热更新冻结

### 新主包可修改

- VM secret 和 opcode count；
- 静态/动态密钥；
- 多态 DLL 结构 secret；
- Pass 组合和级别；
- mapping 策略；
- RandomSeed。

修改后必须重新生成完整 Player 和所有基于该主包的热更新基线。

### 同一主包热更新通常不可修改

- VM secret/opcode count（VM 在 AOT）；
- 静态密钥；
- 多态 DLL structure secret；
- `disableLoadStandardDll` 所对应的主包加载能力。

### 可修改但影响diff

- 动态密钥；
- RandomSeed；
- 热更新相关 mapping 段；
- Pass level 和规则。

如果追求小补丁和 DHE 稳定，不应每次都随机化全部参数。

## 两种热更新策略

### 稳定优先

- 保留 mapping；
- 保持 RandomSeed、规则和级别；
- 保持动态密钥或按兼容策略轮换；
- Call 使用 Delegate（官方针对 DHE 的建议）；
- 只让真实代码变更影响 DLL。

适合频繁小更新、CDN 成本敏感和 DHE 性能优先。

### 差异优先

官方给出的方式：

- 删除 mapping 中热更新相关记录；
- 修改 Default Dynamic Secret Key；
- 修改 RandomSeed；
- 修改 Const/Field/Call level。

会让产物更不相似，但补丁更大、复现更难、堆栈归档更复杂。应作为大版本/高风险版本策略，而不是每次热更默认动作。

## 多主包并存

线上常同时存在多个客户端主包。每个主包可能有不同：

- VM；
- 静态密钥；
- 多态 DLL 结构；
- mapping；
- HybridCLR native runtime；
- Pass 和程序集配置。

热更新服务必须按主包兼容线生成和分发 DLL，不能只按“游戏版本号”提供一套。建议版本键至少包含：平台、渠道、主包版本、架构、Obfuz 配置版本和 HybridCLR runtime 版本。

## 可复现构建

归档：

- Unity/HybridCLR/Obfuz/Obfuz4HybridCLR commit；
- `Obfuz.asset` 快照；
- 所有 XML 规则；
- VM 生成文件哈希；
- secret 版本 ID（非明文）；
- RandomSeed；
- mapping；
- 输入 DLL 与输出 DLL 哈希；
- BuildTarget、Scripting Backend、宏定义。

否则即使有 mapping，也可能无法还原相同产物和线上堆栈。

## mapping冲突与重置

官方 FAQ 提到旧版本 mapping 对带参同名 property 或非法 IL2CPP 名称可能造成问题。删除 mapping 会解决历史脏记录，但会让全部符号重新分配，影响：

- 热更新 diff；
- 旧日志还原；
- DHE；
- 跨版本分析。

正确流程：

1. 备份旧 mapping 和对应 DLL。
2. 升级工具。
3. 在新主包边界重建 mapping。
4. 不对仍在线旧主包直接替换基线 mapping。
5. 保留每套 mapping 的日志解析能力。

## 本工程建议

- 在 `Assets/Obfuz` 创建活动配置和 mapping，但不要提交真实 secret 资源。
- ReleaseTools 在构建结束复制 mapping 到版本制品目录。
- PackageNote 增加 `obfuzConfigVersion`、`mappingId`、`vmId` 等非秘密标识。
- 服务端日志上传同时包含 App/资源包/热更新版本。
- CI 校验当前 Git mapping 已提交且构建后无未预期修改。
