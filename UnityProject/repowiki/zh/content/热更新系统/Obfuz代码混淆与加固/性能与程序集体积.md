# 性能与程序集体积

## 总原则

Symbol Obfus 几乎不增加运行时成本。其他 Pass 都会增加指令、间接调用、解密、缓存、静态数据或分支，影响大小取决于命中范围和执行频率，不能用一个全局百分比概括。

## Pass成本模型

| Pass | CPU | GC/内存 | DLL/IL2CPP体积 | 主要风险 |
|---|---|---|---|---|
| Symbol | 极低 | 极低 | mapping 外几乎无 | 兼容性 |
| RemoveConstField | 极低 | 极低 | 可能略减 | 反射读取 const |
| Const数值 | 每次解密或缓存一次 | 缓存增加静态字段 | RVA/调用增加 | 热循环 |
| Const字符串 | 解密与UTF-8转换 | 未缓存会GC，缓存会常驻 | RVA增加 | 大量文本 |
| Expr | 增加算术/位操作 | 低 | 方法体增加 | 高频数学 |
| FieldEncrypt | 每次读写 | 低到中 | 访问器/IL增加 | 高频字段、序列化 |
| Call | 间接调用、首次解密 | delegate模式有对象/表 | dispatch/delegate增加 | 高频小函数 |
| ControlFlow | switch/状态分支 | 低 | 方法和C++显著增加 | 分支、编译时间 |
| EvalStack | 取决实现 | 取决实现 | 增加 | 当前默认不可用 |
| Watermark | 低 | 少量 | 少量增加 | 无直接保护性能收益 |
| Garbage Code | 若不执行则低 | 编译/包体增加 | 可大幅增加 | 构建时间、商店限制 |

## 官方DLL体积测试如何理解

官方 `impact-dll-size.md` 用特定样本对各 Pass 的程序集大小影响做测试。结论更适合比较“哪些 Pass 倾向膨胀”，不应直接套用百分比到本项目，因为结果取决于：

- 原始方法数量与大小；
- 常量密度；
- 被调用方法签名分组；
- 控制流基本块数量；
- 缓存策略；
- mapping 与调试信息；
- 是否 IL2CPP；
- 压缩和 AssetBundle 分块。

通常 Symbol 影响最小；Call、ControlFlow、EvalStack 和多级 Const 会明显扩大 DLL；垃圾代码可主动产生最大增量。

## 加密级别

Const、Field、Call 的 level 取 `1-4`。官方统一建议 `1`，因为：

- 开启随机 VM 和 ops 已能破坏直接识别；
- 更多操作对自动分析增加有限；
- 每次解密成本近似随指令数增加；
- 方法体和 IL2CPP 输出更复杂。

除非有基准证明收益，不要把高等级当成“更安全”的默认。

## 热路径策略

默认排除或降级：

- `Update/LateUpdate/FixedUpdate`；
- UI 列表滚动和批量创建；
- 动画、物理、寻路、渲染；
- 网络序列化与包解析循环；
- 大量集合迭代；
- Burst/Jobs；
- 日志格式化和本地化热点。

关键逻辑若在热路径，应优先通过架构把“高价值判断”拆成低频方法，再只保护该方法。

## 常量缓存权衡

- 循环内数值：缓存通常优于重复解密。
- 非循环数值：默认不缓存，避免静态字段膨胀。
- 字符串：默认缓存减少 GC，但会增加常驻内存。
- 大量一次性字符串：可选择不缓存，避免永久驻留。

需要同时测启动峰值、运行帧耗和内存，而不是只测单次调用。

## Call模式选择

Dispatch 与 Delegate 运行性能接近。选择重点：

- Dispatch：结构简单、普遍适用；
- Delegate：增量变化更稳定，适合 HybridCLR DHE；
- 高频极小方法：都可能让间接调用成本占比过高，应排除；
- `maxProxyMethodCountPerDispatchMethod` 不宜过大。

## ControlFlow策略

提高基本块最小指令数，只保护较大块，可减少：

- switch case 数；
- 方法体膨胀；
- IL2CPP C++ 代码量；
- 分支预测损失。

控制流最适合少量安全关键、低频、逻辑分支明显的方法。

## 测试方法

建立四套基线：

1. 无混淆。
2. Symbol + RemoveConstField。
3. 计划生产规则。
4. 极限规则，用于发现上限和兼容问题。

记录：

- DLL 与 AssetBundle 压缩前后大小；
- IL2CPP 生成 C++ 大小和编译时间；
- Player 启动时间；
- 热更新 DLL 加载时间；
- 首次执行解密尖峰；
- 关键场景 CPU/GC/内存；
- 热更新补丁 diff；
- 崩溃率和堆栈可读性。

## TEngine建议基线

```text
GameLogic/GameProto：Symbol + RemoveConstField
协议/DTO/序列化：只做Symbol且保留协议成员名，禁用函数体高成本Pass
核心算法：Const level 1 + Expr Basic
关键低频调用链：Call Dispatch/Delegate level 1
少量安全方法：ControlFlow Basic
少量关键状态：FieldEncrypt level 1
UI/Update/资源/网络底层：函数体Pass默认排除
```
