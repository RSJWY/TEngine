# 函数调用与控制流混淆

## 函数调用混淆

Call Obfus 隐藏 IL 中直接可见的调用目标。普通 IL 的 `call/callvirt` 明确包含目标 MethodRef；混淆后会通过生成的 dispatch 或 delegate 间接调用，并把目标索引加密到首次执行时才解密。

## Dispatch原理

1. 按函数签名对目标方法分组。
2. 为每个目标分配组内 index。
3. 使用当前 Encryption Scope 把 index 加密。
4. 原调用点改为调用同签名 `$Dispatch(..., encryptedIndex)`。
5. 运行时解密 index，通过 switch/表选择真实目标。

反编译器只能直接看到 dispatch，不能从静态常量立刻确定最终调用。

`maxProxyMethodCountPerDispatchMethod` 控制单个 dispatch 包含的 proxy 数，默认 100，官方建议不超过 1000。过大可能产生巨型方法、IL2CPP 编译负担和分支预测成本。

## Delegate原理

调用点通过延迟初始化的 delegate 数组间接调用。delegate 在运行时根据解密后的 index 绑定实际方法。

官方比较：

| 模式 | 强度/性能 | 增量稳定性 | 推荐场景 |
|---|---|---|---|
| Dispatch | 与 Delegate 接近，生成结构直接 | 代码变化可能重排 dispatch | 大多数项目默认 |
| Delegate | 与 Dispatch 接近 | 变更差异更小 | HybridCLR DHE/重视增量差异 |

对于旗舰版 HybridCLR DHE，较小的代码差异可减少退化为解释执行的方法，因此官方倾向 Delegate。

## 加密级别

Call Obfus 的 level 决定索引使用多少条 ops，范围 `1-4`。官方建议 `1`。主要安全收益来自“间接调用 + 运行时解密”，不是堆叠更多简单 ops。

## 被调用目标白名单

Call 规则同时控制：

1. 哪些调用点参与混淆；
2. 哪些被调用方法不得成为代理目标。

`whitelist` 可按 assembly/type/method 通配排除目标。常见白名单：

- mscorlib/System 基础库；
- UnityEngine 高频 API；
- P/Invoke、native callback；
- 反射、序列化和动态代理敏感方法；
- 泛型/签名复杂、工具链已知不兼容的方法；
- 性能热路径。

`obfuscateCallToMethodInMscorlib` 默认 false；它与 whitelist 同时生效，任一禁用都会排除调用。

## 调用点规则

规则层级 global → assembly → type → method，使用 `obfuscationLevel`：`None/Basic/Advanced/MostAdvanced`。默认覆盖范围应通过小样本验证，生产上建议默认 None/Basic，再对关键方法提高。

## 控制流混淆

Control Flow 当前官方算法为控制流平坦化：

```text
原始基本块 A -> B/C -> D
       ↓
while/switch 状态机
  case 0: 执行A; state = ...
  case 1: 执行B; state = ...
  case 2: 执行C; state = ...
  case 3: 执行D; exit
```

它破坏自然的 if/loop/try 结构，让反编译输出难以还原原始流程。

### Min Instruction Count

`Min Instruction Count Of Basic Block To Obfuscate` 默认 3。阈值越小，更多短基本块被平坦化，体积和分支成本越高。短 getter、简单条件和自动生成方法通常没有必要处理。

### 规则

层级 global → assembly → type → method，同样以 `obfuscationLevel` 控制。官方文档中多处误写为“常量加密/函数调用”，实际应理解为控制流级别。

## 组合效果

Call + ControlFlow 组合会让调用关系和调用点所在流程同时失真：

- 静态分析先要还原状态机；
- 再识别 dispatch/delegate；
- 再还原 index 解密；
- 最终才能确定调用目标。

代价也叠加：

- 方法体变大；
- IL2CPP C++ 输出膨胀；
- 编译时间上升；
- CPU 分支更多；
- 崩溃堆栈出现生成方法；
- 热更新增量差异扩大。

## 适用范围

推荐：

- 登录/支付/风控流程；
- 战斗结算与关键校验；
- 协议签名和密钥派生；
- 核心状态机；
- 少量反作弊逻辑。

排除：

- `Update/LateUpdate/FixedUpdate` 高频逻辑；
- UI 列表刷新；
- 渲染、物理、动画数学；
- 序列化/网络底层；
- Burst Job；
- 极大方法、复杂异常处理、迭代器/异步状态机，除非验证通过。

## 调试与堆栈

混淆后可能出现 `$Dispatch`、delegate 初始化和状态机生成方法。应使用 mapping 还原符号，并在 DeobfuscateStackTrace 中启用移除 Obfuz 生成函数选项。线上错误分析仍应保留原始混淆堆栈，避免清理过程丢失关键 offset。
