# 反射与序列化兼容

## 根本问题

编译期 IL 引用能被 Obfuz 同步改写，字符串不能。任何把 CLR 名称当作运行时协议的逻辑，都可能在符号混淆后失效：

```csharp
Type.GetType("GameLogic.LoginService");
type.GetMethod("Login");
Enum.Parse(typeof(State), "Ready");
container.Resolve("GameLogic.LoginService");
```

解决方案只有三类：保名、映射、或改协议。

## 离线兼容检测

Symbol 设置中的 `Detect Reflection Compatibility` 扫描典型反射 API，输出潜在问题。它无法理解动态字符串来源，因此：

- 常量字符串通常可高置信定位；
- 拼接、配置、网络下发只能报告风险；
- 某些库内部反射会产生误报；
- 未报告不代表绝对安全。

建议建立告警登记表：调用位置、目标、处理方式、验证用例和责任模块。

## 方案一：禁用名称混淆

适合外部协议必须长期使用原始名称的目标。

方式：

- `[ObfuzIgnore(ObfuzScope.TypeName/MethodName/...)]`；
- Symbol XML 规则；
- 自定义 RenamePolicy。

优点是兼容简单，缺点是直接降低保护范围。应尽可能只保留协议所需层，例如只保留 TypeName，不要对整个类型 `All`。

## 方案二：ObfuscationTypeMapper

TypeMapper 维护“混淆后 Type ↔ 原始类型全名”的运行时映射。可用原始名称查找真实类型，或从 Type 得到原始名称。

适合：

- IOC/服务定位；
- XLua 注册；
- 配置保存原始类型名；
- 自研序列化类型判别器；
- 日志与调试展示。

映射必须在查询前注册。不要把 mapping XML 整体随客户端加载；运行时只注册业务需要的最小类型集合。

## 方案三：ObfuscationInstincts

使用：

```csharp
ObfuscationInstincts.RegisterReflectionType<MyType>();
```

Obfuz 在混淆阶段识别泛型参数和调用位置，提取 `MyType` 的原始全名并生成正确注册逻辑。这样避免手写：

```csharp
ObfuscationTypeMapper.RegisterType<MyType>("Old.Namespace.MyType");
```

手写字符串会在重构后过期，Instinct 则由编译器 Type 引用驱动。它属于编译期提示，不应被当成普通运行时业务调用。

## 方案四：改用稳定业务ID

最稳妥的长期设计是不要把 CLR 名称当协议：

```csharp
[ServiceId("login")]
public sealed class LoginService { }
```

或生成 `TypeId -> Type` 表。业务 ID 可独立于类重构和混淆，协议更稳定，也避免大量保名。

## Unity内置序列化

Unity Scene、Prefab、ScriptableObject、MonoBehaviour 依赖脚本 GUID、类型和字段序列化规则。Obfuz 内置策略会保护常见目标，但应理解边界：

- 类型名/namespace 在某些序列化和引擎回调中必须稳定；
- public 或 `[SerializeField]` 字段名可能参与数据持久化；
- `[FormerlySerializedAs]` 是源码重命名迁移工具，不等于可随意混淆；
- UnityEvent 持久化方法名可能在资产中以字符串保存；
- Animator、Timeline、Binding、SendMessage 等也可能依赖名称。

所有包含持久化 Unity 数据的类型默认应保守处理，并通过构建后 Player 加载真实资产验证。

## Newtonsoft.Json等第三方序列化

### 默认字段/property名

若 JSON key 直接来自 CLR 成员名，符号混淆会改变协议。处理方式：

- 使用 `[JsonProperty("stable_name")]`；
- 使用显式 ContractResolver；
- 对协议 DTO 保名；
- 生成稳定序列化元数据。

### 类型信息

启用 `TypeNameHandling` 等功能会把类型全名写进 JSON，混淆和版本升级都可能破坏反序列化，也存在安全风险。应使用受控 binder 和稳定业务 type id。

### 字段加密

直接序列化字段可能拿到密文存储或无法访问改写字段。敏感内存模型与 DTO 应分离，详见[字段加密](./字段加密.md)。

## Enum和字符串

`Enum.Parse`、枚举 JSON 字符串和配置表枚举名可能依赖原始成员名。选择：

- 保留枚举类型和成员名；
- 使用显式数值或稳定字符串映射；
- 自定义 Converter；
- 构建期生成映射表。

## TEngine重点检查

- `ProcedureLoadAssembly` 对 `GameApp` 和 `Entrance` 的反射调用；
- UI 类型名作为资源地址；
- `GameScene`、流程、模块或事件的字符串注册；
- YooAsset address 是否由 `typeof(T).Name` 派生；
- 配置 JSON 是否使用类型或字段名；
- 代码生成绑定是否通过反射找字段/方法；
- 调试、日志和热更新协议中的程序集限定名。
