# 常量与表达式混淆

## 常量加密

Const Encrypt 将 IL 中的明文常量替换为运行时解密表达式。官方文档列出的支持类型包括：

- byte/sbyte、short/ushort、int/uint、long/ulong；
- IntPtr/UIntPtr；
- float、double；
- string；
- 简单类型的一维或多维数组。

但同一文档的规则表又写明 `encryptArray` “目前不支持常量数组加密、配置无实际效果”，与前面的支持列表冲突。接入时必须用当前 `3.1.0` 实际样本确认数组行为，不能仅依据文档声明。

## RVA双层解密

核心流程：

1. 编辑器使用 `EncryptionService<Scope>.Encrypt` 计算常量密文。
2. 密文保存到程序集 RVA 连续数据区。
3. IL 常量替换为 `DecryptFromRvaInt/Long/Float/Double/String/Bytes` 等调用。
4. 运行时先解密 RVA 数据块，再解密其中的具体值。

```text
int cost = 100;
        ↓
int cost = EncryptionService<Scope>
    .DecryptFromRvaInt(rvaData, offset, ops, salt);
```

RVA 可隐藏大量连续数据，但会增加程序集数据段和辅助初始化代码。

## 加密级别

级别范围 `1-4`，表示每个对象使用的加密指令数量。官方明确建议保持 `1`：只要使用随机 ops 和 VM，提升到 2-4 对破解难度的增益有限，却线性增加解密指令和生成代码复杂度。

## 常量白名单

规则文件可全局排除：

| type | 含义 |
|---|---|
| `int`、`long` | 精确值列表 |
| `string` | 单个精确字符串 |
| `int-range`、`long-range` | 数值闭区间，可省略上下界 |
| `float-range`、`double-range` | 浮点范围 |
| `string-length-range` | 字符串长度范围 |
| `array-length-range` | 数组长度范围 |

适合排除：0/1/-1、短枚举值、循环上限、空字符串、极短 UI 文本以及对性能无保护价值的常量。

## 常量规则字段

| 字段 | 默认 | 说明 |
|---|---:|---|
| `disableEncrypt` | 0 | 总开关，优先级高于各类型开关 |
| `encryptInt/Long/Float/Double/String/Array` | 1 | 类型开关 |
| `encryptConstInLoop` | 1 | 是否加密循环内数值 |
| `encryptStringInLoop` | 1 | 是否加密循环内字符串 |
| `cacheConstInLoop` | 1 | 循环内数值延迟解密后缓存 |
| `cacheStringInLoop` | 1 | 循环内字符串缓存 |
| `cacheConstNotInLoop` | 0 | 非循环数值默认不缓存 |
| `cacheStringNotInLoop` | 1 | 非循环字符串默认缓存以避免重复 GC |

规则按 global → assembly → type → method 继承。

### 性能含义

- 循环内每次解密会显著放大开销，应缓存或排除。
- 字符串解密会创建字符串，默认缓存是合理的，但增加静态字段和驻留内存。
- 大量非循环数值缓存会扩大生成类型和静态初始化，不一定更快。
- 常量保护应集中在协议码、关键阈值、算法参数和敏感文本，不宜覆盖渲染/物理热路径中的普通数字。

## Remove Const Field

C# `const` 常被编译器内联，但字段元数据和默认值可能仍出现在 DLL 中。Remove Const Field 删除这些可直接读取的常量字段，减少反编译暴露。

不会删除：

- 被 `[ObfuzIgnore(ObfuzScope.Field)]` 影响的字段；
- 被规则文件列出的保留字段；
- Obfuz 判断不能安全移除的目标。

规则语义与其他 Pass 不同：规则中匹配的 field 是“保留列表”，而不是“要移除列表”。

应保留依赖反射读取字段元数据的常量，例如：

- `GetField`/`GetRawConstantValue`；
- 编辑器工具枚举常量；
- 第三方库把 public const 当作注册协议；
- 自动生成器在构建后读取已编译 DLL。

## 表达式混淆

Expr Obfus 将算术和位运算表达式替换为等价但更复杂的表达式，以破坏反编译器的直接可读性。官方列出的能力围绕：

- 数值算术表达式；
- 位运算和移位；
- 与常量结合的等价变换。

其规则层级为 global → assembly → type → method，以 `obfuscationLevel` 控制 `None/Basic/Advanced/MostAdvanced`。

表达式混淆不依赖字段存储，但会增加 IL 指令数。应重点保护：

- 校验算法；
- 经济数值换算；
- 协议编码；
- 关键状态转换；
- 简短而敏感的算法表达式。

不建议覆盖：

- 高频 Update 数学；
- 大量向量/矩阵计算；
- Burst job 或要求特定 IL 形态的代码；
- 数值稳定性敏感的浮点路径，除非已做平台回归。

## 推荐组合

```text
Symbol + RemoveConstField
  -> 低成本基础保护

Const(level 1) + 字符串缓存
  -> 隐藏关键常量与文本

Expr(Basic/Advanced，仅核心方法)
  -> 增加算法阅读成本
```

先应用常量加密，再应用表达式混淆时，最终 IL 会同时出现 RVA 解密与复杂表达式。组合强度更高，但性能和体积也叠加，必须通过方法级规则控制。
