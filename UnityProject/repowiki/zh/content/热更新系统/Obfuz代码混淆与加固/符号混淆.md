# 符号混淆

## 作用范围

Symbol Obfus 会改写：

- namespace 与类型名；
- 字段名；
- 方法名和参数名；
- property 名及 getter/setter 名；
- event 名及 add/remove/fire 方法名。

它通常是收益最高、运行时成本最低的 Pass。主要风险不是性能，而是字符串协议、反射、序列化、Unity 资产引用和外部程序集引用是否仍能找到改名后的元数据。

## symbol mapping

`symbol-mapping.xml` 记录原始名称与混淆名称的稳定映射，承担两个职责：

1. 下次混淆优先复用旧名称，减少热更新和二进制差异。
2. 使用 DeobfuscateStackTrace 将线上混淆堆栈还原为源码符号。

因此必须：

- 纳入版本管理；
- 按主包/热更新版本归档；
- 与实际发布 DLL 一一对应；
- 限制访问，不随客户端公开分发；
- 备份到构建制品库或日志解析服务。

`Keep Unknown Symbol In Symbol Mapping File` 默认开启。Unity 构建裁剪可能让某次构建看不到旧符号；保留未知记录可以避免它们被删除后重新分配名字，破坏增量稳定性。

## 混淆名与命名空间

### Obfuscated Name Prefix

默认 `$`。即使为空也能产生不冲突名称，但前缀能快速区分生成符号。不要把前缀当成安全特征；攻击者也可据此过滤混淆符号。

### Use Consistent Namespace

开启时，相同原始 namespace 共享相同混淆 namespace；关闭时，同名 namespace 在不同上下文可能映射不同。空 namespace 保持为空。

生产上通常保持开启：

- mapping 更易理解；
- 增量变化更稳定；
- 同一命名空间的跨程序集关系更清晰。

关闭可以增加随机性，但会扩大 mapping 和变更差异。

## Debug模式

Debug 模式把 `Apple` 稳定改为类似 `$Apple`，便于确认哪些符号被选中。官方说明它会忽略正式混淆规则和正式 mapping 输入，并输出独立 debug mapping。

适合：

- 初次接入检查覆盖范围；
- 定位某类型是否因内置策略被保护；
- 调查反射或序列化错误；
- 对照混淆前后堆栈。

不适合作为正式保护，因为名称仍可读。

## 反射兼容检测

`Detect Reflection Compatibility` 会扫描可能依赖原始字符串名称的代码并报告警告/错误，例如：

- `Type.GetType("Namespace.Type")`；
- `Assembly.GetType`；
- `GetMethod/GetField/GetProperty/GetEvent`；
- `Enum.Parse`；
- `Activator.CreateInstance` 与配置驱动类型；
- 某些序列化、IOC 和注册代码。

检测只能指出风险，无法判断业务字符串是否一定匹配该元数据。每条告警都应人工分类为：真实问题、已通过 TypeMapper 处理、已通过规则保名、或确认无关。不要为了消除日志直接全局关闭。

## 默认排除目标

Obfuz 内置 .NET/Unity RenamePolicy，通常会保护下列目标：

- 需要与运行时约定名称匹配的特殊方法；
- override/interface 实现中不能独立改名的成员；
- P/Invoke、COM、序列化或框架约定元数据；
- Unity `MonoBehaviour`、`ScriptableObject`、`[Serializable]` 等需要资产/序列化稳定性的类型或成员；
- Unity 消息方法，如 `Awake`、`Start`、`Update`；
- `[RuntimeInitializeOnLoadMethod]` 类型/方法；
- Burst、DOTS、生成代码和部分 UI/EventSystems 回调。

具体保护范围随版本变化。必须以当前源码和实际混淆结果为准，不能把文档示例当作永久契约。

## 自定义RenamePolicy

若项目存在自有框架协议，可实现自定义 RenamePolicy 并将类型全名加入 `Custom Rename Policy Types`。适合统一保护：

- 所有实现某接口的类型名；
- 带特定 Attribute 的成员；
- 配置驱动注册类；
- 网络协议 DTO；
- UI 资源名等于类型名的类；
- 自研序列化/依赖注入入口。

策略类型全名不含程序集名，因此必须在 AppDomain 内唯一。

## 规则文件模型

### 节点层级

```xml
<obfuz>
  <assembly name="GameLogic" obName="1">
    <type name="GameLogic.UI.*"
          obName="0"
          applyToMembers="method,property,event"
          applyToNestedTypes="1"
          modifier="public,protected"
          classType="class"
          inherit="GameLogic.UIBase"
          hasCustomAttributes="My.KeepNameAttribute">
      <field name="_*" obName="1" />
      <method name="On*" obName="0" />
      <property name="*" obName="1" applyToMembers="propertyGetterSetterName" />
      <event name="*" obName="1" applyToMembers="eventAddRemoveFireName" />
    </type>
  </assembly>
</obfuz>
```

顶层必须是 `obfuz`，次级是 `assembly`。一个目标可匹配多条规则，最后一个非空 `obName` 生效。

### obName继承

- `1/true`：允许改名；
- `0/false`：保留名称；
- 空或未设置：继承。

成员只有在父 type 的 `applyToMembers` 包含对应类别时才继承父 `obName`。如果 assembly 未指定 `obName`，待混淆程序集默认允许改名。

### type过滤器

| 属性 | 含义 |
|---|---|
| `name` | 通配类型全名；嵌套类型用 `/` |
| `modifier` | public/protected/private 组合 |
| `classType` | class/struct/enum/interface/delegate 组合 |
| `inherit` | 继承任一类型或实现任一接口，使用类型全名 |
| `hasCustomAttributes` | 含任一指定 Attribute |
| `applyToNestedTypes` | 将类型名规则传播给所有嵌套类型 |

### applyToMembers

可组合：`field`、`method`、`propertyName`、`propertyGetterSetterName`、`property`、`eventName`、`eventAddRemoveFireName`、`event`。官方示例还列出 `none`、`all` 或 `*` 等表达。

property/event 的元数据名和访问器方法名是不同对象，要根据外部协议分别保护。

## Attribute与规则的选择

优先使用集中规则处理大范围、稳定协议；使用 `[ObfuzIgnore]` 处理紧贴代码语义的少量入口。例如：

- `GameApp.Entrance` 是明确反射入口，Attribute 合理；
- 整个 `GameLogic.UI.*` 类型名与资源名绑定，应使用统一规则或基类传播；
- 某个 Newtonsoft DTO 集合应通过 Attribute/自定义策略统一保护，而不是逐字段注解。
