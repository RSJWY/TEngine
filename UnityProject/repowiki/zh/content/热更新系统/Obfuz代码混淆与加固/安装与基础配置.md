# 安装与基础配置

> **当前 Fork 提示**：包已按本仓库方式本地化集成，静态/动态密钥初始化和多态 DLL 产物转换均已有项目实现。旧 `BuildAssets And CopyTo AssemblyTextAssetPath` 菜单描述不再是完整构建流程。参见 [HybridCLR集成](HybridCLR集成.md)。

## 包组成

典型 Unity + HybridCLR 项目包含三部分：

| 包 | 作用 |
|---|---|
| `Obfuz` | IL 重写器、编辑器配置、运行时解密与类型映射 |
| `HybridCLR` | 热更新运行时、DLL 编译、AOT 元数据补充 |
| `Obfuz4HybridCLR` | 解决 dnlib、裁剪、热更新 DLL 混淆和多态 DLL 的集成问题 |

安装时应锁定明确 commit/tag 或稳定包版本。只使用浮动 Git URL 会降低 CI 可复现性。本工程的 `Packages/manifest.json` 当前只显式列出 HybridCLR，未发现 Obfuz/Obfuz4HybridCLR 声明；如果它们通过本地包、嵌入包或其他方式提供，需补充来源说明和 CI 安装步骤。

## Unity与平台支持

官方文档声明支持 Unity `2021.3+`，包括 Mono 和 IL2CPP 支持的平台。多态 DLL 依赖 HybridCLR `8.4.0+` 的自定义 DLL 结构能力。实际采用版本还必须与当前 Unity、HybridCLR 分支和 Obfuz4HybridCLR 匹配，不应仅按最低版本推断兼容。

## Editor菜单

官方 Obfuz 菜单包含以下核心操作，具体名称可能随版本变化：

- 打开 `ObfuzSettings`；
- 生成 Encryption VM；
- 生成 Secret Key；
- 生成垃圾代码；
- 执行或辅助构建混淆；
- 堆栈还原相关工具。

Obfuz4HybridCLR 会增加 `HybridCLR/ObfuzExtension/...` 菜单，用扩展版 `GenerateAll` 和编译混淆流程替换原始 HybridCLR 命令。

本工程额外在 [BuildDLLCommand.cs](file://Assets/TEngine/Editor/HybridCLR/BuildDLLCommand.cs) 提供：

```text
Obfuz/Define Symbols/Enable Obfuz
Obfuz/Define Symbols/Disable Obfuz
HybridCLR/Build/BuildAssets And CopyTo AssemblyTextAssetPath
```

其中 `ENABLE_OBFUZ` 同时被用作 dev/release 构建模式标记。因此开关混淆会影响：

- 热更新 DLL 是否进入 Obfuz 分支；
- `UpdateSetting.IsDevelopmentBuild`；
- YooAsset `PackageNote` 中的模式；
- PDB 生成、加载和 Release 残留检查；
- Exe 与资源包模式匹配校验。

## ObfuzSettings全局配置

配置序列化在 [Obfuz.asset](file://ProjectSettings/Obfuz.asset)。

### Build Pipeline Settings

| 字段 | 含义 | 发布注意 |
|---|---|---|
| `enable` | 是否在 Unity Player 构建回调中执行混淆 | 只影响自动构建，不阻止主动调用 `Obfuscator` |
| `linkXmlProcessCallbackOrder` | link.xml 处理回调顺序 | 与其他 Linker Processor 的顺序冲突需验证 |
| `obfuscationProcessCallbackOrder` | 程序集混淆回调顺序 | 应在需要读取原始/混淆程序集的自定义处理器之间正确排序 |

本工程当前 `enable: 0`，即自动 Player Build 混淆关闭；热更新 DLL 仍可能通过 `BuildDLLCommand` 的显式调用单独混淆。

### Assembly Settings

| 字段 | 含义 |
|---|---|
| `assembliesToObfuscate` | 真正被混淆的程序集，不带 `.dll` |
| `nonObfuscatedButReferencingObfuscatedAssemblies` | 自身不混淆，但引用需跟随重写的程序集 |
| `additionalAssemblySearchPaths` | 项目外 DLL 或同名 DLL 优先搜索路径 |
| `obfuscateObfuzRuntime` | 是否混淆 `Obfuz.Runtime`，官方强烈建议启用 |

详细语义见[程序集分类与依赖处理](./程序集分类与依赖处理.md)。

### Obfuscation Pass Settings

- `enabledPasses` 是全局硬上限。
- `ruleFiles` 用于分 assembly/type/member 调整启用组合。
- 如果某个 Pass 不在 `enabledPasses`，专用规则无法重新开启它。

当前工程为 `enabledPasses: -1`，通常表示枚举 `All`。这不是稳妥的生产默认：它会让当前默认 Builder 中所有已注册 Pass 都参与，且专用规则均为空，相当于大范围应用默认行为。

### Secret Settings

| 字段 | 当前值 | 评估 |
|---|---|---|
| `defaultStaticSecretKey` | `Code Philosophy-Static` | 示例默认值，必须替换 |
| `defaultDynamicSecretKey` | `Code Philosophy-Dynamic` | 示例默认值，必须替换 |
| 静态密钥输出 | `Assets/Resources/Obfuz/defaultStaticSecretKey.bytes` | Resources 明文资源易提取，仅适合示例 |
| 动态密钥输出 | `Assets/Resources/Obfuz/defaultDynamicSecretKey.bytes` | 不应把动态密钥直接随主包发布 |
| `randomSeed` | `0` | 尚无版本随机化策略 |
| `assembliesUsingDynamicSecretKeys` | 空 | 当前未指定动态 Scope 程序集 |

静态密钥必须在相应混淆代码首次执行前初始化；动态密钥一般用于热更新程序集，并可在下载或认证后加载。

### Encryption VM Settings

| 字段 | 说明 |
|---|---|
| `codeGenerationSecretKey` | 决定生成哪套加密指令代码；主包发布后不得随热更新改变 |
| `encryptionOpCodeCount` | 指令数量，必须为不小于 64 的 2 次幂，默认 256 |
| `codeOutputPath` | VM C# 输出路径，默认 `Assets/Obfuz/GeneratedEncryptionVirtualMachine.cs` |

当前工程仍使用 `Obfuz` 默认 secret，且输出文件不存在。正式发布前必须生成专用 VM，并确认它所在程序集和初始化时机。

### Symbol Obfus Settings

关键字段：

- `debug`：Debug 模式将名字稳定改为 `$原名`，便于定位，但忽略正式 mapping 输入和规则效果；
- `obfuscatedNamePrefix`：默认 `$`；
- `useConsistentNamespaceObfuscation`：同名命名空间是否映射为相同结果；
- `detectReflectionCompatibility`：扫描潜在字符串反射风险；
- `keepUnknownSymbolInSymbolMappingFile`：避免 Unity 裁剪导致 mapping 记录不稳定；
- `symbolMappingFile`：正式映射，必须版本管理；
- `debugSymbolMappingFile`：Debug 输出映射；
- `customRenamePolicyTypes`：自定义改名策略类型全名。

### 各Pass设置

| Pass | 全局设置 |
|---|---|
| Const Encrypt | `encryptionLevel`、规则文件 |
| Remove Const Field | 保留规则文件 |
| Eval Stack | 规则文件；`3.1.0` 默认 Builder 未注册 |
| Expr | 规则文件 |
| Field Encrypt | `encryptionLevel`、规则文件 |
| Call Obfus | Proxy Mode、level、dispatch 容量、mscorlib 开关、规则文件 |
| Control Flow | 基本块最小指令数、规则文件 |
| Watermark | 文本、签名长度 |

### Garbage Code Settings

任务可配置：随机种子、命名空间、类名前缀、类数、每类方法数、字段数、代码类型和输出路径。垃圾代码主要用于降低二进制相似度，不应与核心防护强度混为一谈。

### Polymorphic DLL Settings

| 字段 | 当前值 | 发布要求 |
|---|---|---|
| `enable` | `1` | 还需运行扩展 GenerateAll 并核实生成的 C++ 注入 |
| `codeGenerationSecretKey` | `obfuz-polymorphic-key` | 默认值，必须替换；与主包结构绑定 |
| `disableLoadStandardDll` | `0` | 初期保持关闭更利于调试与回滚，成熟后再评估 |

## 首次接入检查表

1. 确认包来源、版本和许可证。
2. 打开 Settings，先不要直接使用 `All` 发布。
3. 完成程序集依赖图。
4. 配置低风险 Symbol/RemoveConstField 规则。
5. 替换所有默认 secret，生成 VM 和密钥。
6. 实现 Encryptor 初始化并保证先于混淆代码。
7. 建立 mapping 版本管理目录。
8. 跑反射兼容检测并人工处理每条告警。
9. 在真机而非当前源码仍存在的 Editor AppDomain 中验证混淆 DLL。
10. 通过后再逐项开启高成本 Pass。
