# Fork Editor 与构建工作流

## 打包工具窗口

菜单：`Build/打包工具窗口`。窗口基于 Odin，构建与运行时包配置共同读写 `UpdateSetting.RuntimePackages`，不要再维护第二份包列表。

实际流程按启用项执行：

```text
编译热更 DLL -> 构建资源包 -> 发布整理 -> 最小包处理
-> 构建 Player -> 编译 Inno Setup 安装包
```

- 每个包可独立选择构建管线、加密方式、是否初始化、更新 manifest、参与下载和保存版本。
- `BuiltinBuildPipeline` 只作旧数据兼容，不在新 UI 中提供。
- CodePackage 默认 ArchiveFile + ChaCha20。
- 资源包表格使用延迟保存；关闭窗口、显式保存或开始构建前必须 flush。
- AssetBundle 或 Player 构建失败必须阻断安装包阶段，不能继续使用旧产物。

## 构建产物目录

```text
Releases/
├── Bundles/
├── Windows/
│   ├── setup.iss
│   ├── setup.generated.iss
│   ├── build/
│   └── setup/
├── Linux/
│   └── build/
└── Publish/{平台}/{包名}/
```

- AB 默认根目录：`./Releases/Bundles/`。
- 发布整理默认根目录：`./Releases/Publish/`。
- Windows/Linux Player 进入 `Releases/{平台}/build/`。
- Android/iOS/MacOS/WebGL 仍使用 `Output/Player/{平台}/`，不要擅自统一。
- 发布整理使用运行时远端平台名，如 `Windows64`，不要直接使用 `StandaloneWindows64`。

## Inno Setup

- `Releases/Windows/setup.iss` 是受版本控制的模板。
- `setup.generated.iss` 是实际编译脚本，首次打开面板时从模板生成，通常应忽略版本管理。
- 日常参数只写入 generated 文件；普通构建不能覆盖模板。
- `MyAppId` 只在模板手工维护，窗口不回写；它决定升级覆盖身份。
- `MyAppEnglishName` 只用于默认安装目录，中文 `MyAppName` 用于显示。
- ISCC 解析顺序：用户路径 -> 注册表 -> PATH -> Program Files。
- ISCC stdout/stderr 必须并行读取，超时或异常路径都要清理 Unity 进度条。

## 构建模式与 Obfuz 面板

- 构建模式窗口：`TEngine/Build/构建模式窗口`。
- 混淆配置窗口：`TEngine/Build/混淆配置窗口`。
- dev/release 由 `ENABLE_RELEASE` 表达，Obfuz 由 `ENABLE_OBFUZ` 表达，两者独立。
- dev 模式可按配置生成/加载 PDB；release 模式不生成 PDB。
- `OBFUZ_INSTALLED` 仅表示包存在，确保关闭 `ENABLE_OBFUZ` 后菜单仍可见。
- 修改 Obfuz 多态参数或首次出多态 App 时，结合 [fork-resource-hotupdate.md](fork-resource-hotupdate.md) 的冻结参数和 `GenerateAll` 约束。

## AOT 与热更新辅助工具

- 同步 AOT 清单：`HybridCLR/Build/Sync AOT Metadata Manifest`。
- 编译并拷贝 DLL 的构建入口会先同步清单，再按 dev/release 和 Obfuz 配置处理产物。
- 热更新版本记录工具：`TEngine/HotUpdate/Package Version PlayerPrefs`，只删除 `RuntimePackages` 展示的 `VersionKey`，禁止 `PlayerPrefs.DeleteAll()`。

## SceneEnumConfig

菜单：`TEngine/场景枚举配置`。

工作流：

1. 同步 YooAsset `Scenes` Group 的收集目录。
2. 检查新增、改名、删除场景。
3. 编辑稳定的 `EnumName` / `EnumValue` 和中文备注。
4. 生成 `SceneType.g.cs`、`SceneConstName.g.cs`、`SceneTypeMapping.g.cs`。

约束：

- 生成文件带 `<auto-generated>`，不要手改。
- 场景用 GUID 跟踪；改名只更新资源地址，不改变已发布枚举值。
- 新枚举值使用 `max + 1`，删除场景保留占位，不复用值。
- 生成前必须确认场景在 YooAsset Scenes Group 收集范围内。
- 修改生成器代码后先等 Unity Editor 程序集重编译完成，再点击生成，避免旧程序集覆盖结果。

## 常用调试工具

- GameObjectPool 调试窗口：`TEngine Tools/Debugger/GameObject Pool`。
- 日志目录：`TEngine/Open Folder/Log Files Path`。
- 构建工具中的 AOT 同步、热更 DLL 编译和发布整理按钮应复用现有 `ReleaseTools` / `BuildDLLCommand`，不要另写平行构建链路。

## Editor 代码约束

- 热更组件的 Inspector 放 `Assets/Editor/`，框架构建工具放 `Assets/TEngine/Editor/`。
- Editor 类继承建议写 `UnityEditor.Editor`，避免 `Editor` 命名空间遮蔽。
- 运行时程序集不能引用 Odin Editor 类型；窗口层可用 view model 包装运行时配置。
- 自动生成文件、资源构建产物和 generated iss 不应作为手工源文件修改。
