# PurrNet 官方文档详细报告

> 基于 PurrDocs 仓库（https://purrnet.dev/docs 的源 markdown）约 90 篇核心文档的系统阅读。

## 一、定位、定价与兼容性

**PurrNet 是 100% 免费的 Unity 高层网络库**：无收入分成、无预付费用、无付费核心功能。收费内容仅限外部服务（如工作室级支持、完整集成模板）。PurrVoice 语音聊天目前处于 Early Access（付费 Discord 成员可用），未来会免费开放。

**兼容性矩阵**：PC / Linux / Mac / Android / iOS / WebGL / Nintendo Switch / PlayStation / Xbox / 专用服务器（Dedicated Server）/ 本地服务器全部支持（✅）。跨平台联机通过 Composite Transport 实现。PurrDiction 支持 Unity 2022 与 Unity 6；PurrLobby 要求 Unity 2022.3+。

**差异化卖点**（unique-to-purrnet.md）：
- **无烘焙（No baking）**：场景 ID 运行时按层级顺序计算，无版本控制冲突
- **无 NetworkObject 组件**：每个 NetworkBehaviour 本身就是 Network Identity，支持组件级所有权
- **Instantiate/Destroy 即生成/销毁**：对象池也挂接同一套 Unity API
- **Network Rules**：用 ScriptableObject 配置整个权限模型，可后期从 Unsafe 换成 ServerStrict 而不改游戏代码
- 泛型 RPC、静态 RPC、可返回值（Awaitable）RPC
- Cookie 系统：断线重连保持相同 PlayerID 与元数据
- 编辑器运行时可直接拖 prefab 进场景自动网络生成

## 三、核心系统

### 1. Network Manager（中枢）
关键设置：Start Server/Client Flags（自动启动条件）、Cookie Scope（Live With Connection / Live With Process / Store Persistently）、Transport、Network Prefabs、Network Rules、Visibility Rules。
**MTU 处理**：`mtuExceededBehaviour` 三种模式——`Fragment`（默认，分片，任一分片丢失则整条丢弃）、`Upgrade To Reliable`、`Drop`。单个 RPC 可用 `[ObserversRpc(channel: Channel.Unreliable, mtuExceeded: MTUBehaviour.Fragment)]` 覆盖全局。`UnreliableSequenced` 上覆盖被忽略（编译期警告）。官方警告：分片是兜底而非大消息方案，必须完整到达的大数据应走可靠通道或 SyncBigData。

### 2. Network Rules（权限模型）
预置三套：**Unsafe**（开发期最自由，人人可 spawn/调 RPC）、**ServerStrict**（全服务器权威，类似 Mirror/FishNet）、**ServerOwner**（折中）。可配置：spawn/despawn 授权、默认 owner、所有权转移规则、谁负责同步数据等。"Include Instantiated Scene Objects"为可选启用，要求所有客户端以相同顺序程序化实例化场景对象，否则 ID 会分歧。

### 3. Network Identity / Ownership / Spawning
- 单个 GameObject 可挂多个 NetworkIdentity，**所有权可按组件分裂**（可设置传播到整个对象）
- `GiveOwnership(PlayerID)` 转移所有权；`isController` = "有 owner 且我是 owner"或"无 owner 且我是 server"
- 生成即 `Instantiate(myObject)`，销毁即 `Destroy(...)`；可重写 `OnSerialize/OnDeserialize` 让数据随 spawn 包一起发送（在 `OnEarlySpawn/OnSpawned` 前可用）
- **Client Spawning Validation**：服务端注册 `networkManager.onClientSpawnValidate += (player, SpawnPacket) => bool`，用 `data.TryGetRawPrefab(nm, out var prefab)` 校验完整 prefab spawn，拒绝则客户端本地回收
- **对象池**：prefab 勾选即启用，仍用 Instantiate/Destroy；`OnPoolReset()` 清理自定义状态，SyncVar/SyncList/SyncDictionary 自动还原初始值；混搭池化可能断引用，用 `[SerializeField] private Reference<MeshRenderer> someRenderer;` 修复；`UnityProxy.InstantiateDirectlyFromPool` 仅本地实例化不触发网络 spawn
- **PlayerIdentity&lt;T&gt;**：静态 `TryGetLocal/TryGetPlayer/allPlayers` 注册表

### 4. Network Modules 与 Sync Types
NetworkModule 是非 MonoBehaviour 的可复用网络组件，可嵌套。**常见坑**（common-pitfalls）：
1. 模块必须是字段/属性，**禁止 List&lt;SyncVar&gt;** 或动态创建
2. 用 `[SerializeField]`/public 可在 Inspector 显示（只读调试用）
3. 初始化放 `OnInitializeModules()`（在网络发数据/分配 ID 之前）
4. **spawn 后绝不能替换模块实例**（会破坏网络）
5. 嵌套必须成树，循环依赖导致编译错误
6. 事件：OnSpawned/OnOwnerChanged/OnDespawned

Sync 类型清单：
- **SyncVar&lt;T&gt;**：`new(5, ownerAuth:true, ownerOnly:true)`；`onChanged` 回调
- **ValidatedSyncVar**：客户端先本地预测立即生效（validated=false 事件），服务器 `serverValidation` multicast 验证（全部返回 true 才通过），通过则广播（validated=true），拒绝则回滚并触发 `onValidationFail(failed, authoritative)`；用 PackedUInt packetId 忽略过期 ack（快速 1→2→3 时只应用最新）
- **SyncLazyRef&lt;T&gt;**：懒解析的 NetworkIdentity 引用，存 GlobalNetworkID，目标未加载时等待，出现后自动解析；赋值 null 全端清除；目标必须已 spawn
- **SyncList/SyncArray/SyncQueue/SyncDictionary/SyncHashset**：API 仿原生集合，`onChanged(SyncListChange{operation,value,index})`；`SetDirty(i)` 手动标脏
- **SyncEvent**：`Invoke(10)` 自动网络广播，Inspector 里像 UnityEvent 一样可配置
- **SyncTimer**：`StartTimer(30f)/PauseTimer(true)/ResumeTimer()`，自动对账（reconcile interval 默认 3s），`manualUpdate:true` + `Advance(Time.deltaTime)` 手动驱动
- **SyncInput&lt;T&gt;**：输入同步（owner 发输入、server 跑逻辑），自动去重只发变化，支持 `hostPing:100f` 模拟 host 延迟保证公平（`_mySyncInput.simulatedHostPing = 250f` 动态调整）；适合 Gang Beasts/Human Fall Flat 类游戏
- **ownerOnly: true**：数据只发 owner 和 server（真服务端过滤），可和 ownerAuth 组合；转移所有权时新 owner 自动补全，旧 owner 保留陈旧副本（敏感数据应在转移前服务端重置）
- **SyncBigData**：给字节数组 + KB/s 限速，自动异步分片；所有权丢失取消上传、重连续传

### 5. RPC 系统
三类：`[ServerRpc]`（RequireOwnership, RunLocally）、`[ObserversRpc]`（RequireServer, BufferLast, RunLocally）、`[TargetRpc(PlayerID target)]`（RequireServer, BufferLast, RunLocally）。
共享参数：`Channel`（默认 ReliableOrdered）、`CompressionLevel`（None/Fast/Best）、`MtuExceeded`、`Immediate`（同帧冲刷、到达即执行，牺牲批处理效率）。
**RPCInfo**：`void TestRpc(int v, RPCInfo info = default)` → `info.sender`。

```csharp
// 泛型（支持所有 RPC 类型 + static/awaitable 组合）
[ServerRpc] private void TestRpc<T, P>(T d1, P d2) { }

// 静态
[ServerRpc] private static void TestRpc(int myNumber) { }

// 可返回值（asyncTimeoutInSec 默认 5）
[ServerRpc(requireOwnership:false, asyncTimeoutInSec:10)]
public async Task<bool> SetReady(RPCInfo info = default) { ... }
var allReady = await shopPhase.SetReady();
```

**本地执行**：`PurrCompilerFlags.EnterLocalExecution()/ExitLocalExecution()` 局部绕网；`[ObserversRpc, LocalMode]` 整方法本地执行。注意是编译器提示、仅限当前函数、不追踪逻辑流。

### 6. Broadcast、Scene、Addressables、InstanceHandler
- **Broadcast**：无 NetworkIdentity 的全局消息（struct 实现 `IPackedAuto`），`InstanceHandler.NetworkManager.Subscribe<T>/SendToAll/SendToServer`；客户端只能发往 server；未认证连接只收 Connection 作用域广播
- **Scene Module**（仅服务端调用）：`sceneModule.LoadSceneAsync("name", settings)`；PurrSceneSettings：mode（Single/Additive）、physicsMode、isPublic（是否拉所有玩家进场景）
- **Addressables**：IL weaving 拦截 `Addressables.InstantiateAsync/ReleaseInstance` 自动 spawn/despawn；或显式 `networkManager.SpawnAddressableAsync(prefabReference)`；支持 Addressable 场景与 RPC
- **InstanceHandler**：`InstanceHandler.NetworkManager` 全局访问；`RegisterInstance<T>/TryGetInstance<T>` 替代单例

### 7. Collider Rollback（延迟补偿）
加 `ColliderRollback` 组件记录历史。客户端：`ShootOnServer(rollbackTick, ray)`（rollbackTick 来自 `networkManager.tickModule.rollbackTick`）。服务端：
```csharp
[ServerRpc(requireOwnership: false)]
private void Shoot(double preciseTick, Ray ray) {
    if (rollbackModule.Raycast(preciseTick, ray, out var hit)) { /* 伤害 */ }
}
```
特色：**不物理移动 collider**（避免触发意外物理事件），而是按 collider 逐个"弯曲射线"求解命中。适合服务器权威移动的游戏。

### 8. BitPacker 序列化
四级方案：`IPackedAuto`（全自动）→ `IPackedSimple`（自写 Serialize）→ `IPacked`（Write/Read 分离）→ **静态扩展方法**（最高性能，自动发现）。可直接 RPC 传 `BitPacker`（`using var writer = BitPackerPool.Get();`）。
**Delta Packers**：`DeltaPacker<T>.Write(packer, old, new)` 只写差异；无 delta 可用时自动回退为"changed 位 + 全值"。无需注册。

### 9. Code Stripping / Bandwidth Profiler / 网络模拟
- **Code Stripping**：Project Settings → Multiplayer → Strip Code Mode，客户端构建自动剥除服务器代码；`[ServerOnly(StripCodeModeOverride.ReplaceWithLogError)]`
- **Bandwidth Profiler**（Tools/PurrNet/Analysis）：实时流量图、逐 RPC 参数检查、丢失分片消息统计（Expired/Evicted/BudgetExceeded/SequencedStale）、会话存取
- **延迟模拟**：UDP/Purr Transport 内置（Min/Max Latency 每向生效、PacketLoss 作用于可靠性层之下、release 构建被编译剔除，需 `SIMULATE_NETWORK` 宏）；全进程节流推荐 Clumsy

### 10. Transports 一览
| Transport | 要点 |
|---|---|
| UDP（默认） | 基于 LiteNetLib；Port/MaxConnections/Address |
| Web | WebGL 用，支持 SSL/Query/Path |
| Composite | 按列表顺序自动选可用 transport，实现跨平台（Web+Steam+EOS 同服） |
| Steam | 需 Steamworks.NET；P2P 或 Game Server；"Steam 不是网络" |
| Purr Transport | 官方免费中继（房间制），6 区域（US×2/EU/AP/巴西/南非）；**默认地址仅限开发，生产需自建** |
| EOS | Epic P2P，需 PlayEveryWare EOS 插件；同 NM StartClient 短路为进程内投递 |
| Local | 不发数据、以 Host 运行，单机复用网络代码 |

## 四、PurrDiction 客户端预测（重点）

**安装**：独立包 `dev.purrnet.purrdiction`（git/OpenUPM），每场景加 PredictionManager，勾选 Built-In Systems（hierarchy/players/time/random/2D/3D 物理）**且** Physics Provider 对应开关；**不要用 FixedUpdate 驱动物理**，PredictionManager 在 tick 内推进物理。

**双层心智模型**：Simulation（tick 率，存输入/状态历史可回滚重放）+ View（每渲染帧，平滑展示不参与逻辑）。服务器始终权威。

**预测策略（Prediction Policies）**——只影响客户端，服务器永远全部模拟：
| 策略 | 行为 | 适用 |
|---|---|---|
| FullPrediction | 本地超前模拟 + 回滚重放 | 本地玩家、关键物理 |
| ServerRelay | 只跑已验证 tick（远程刚体变 kinematic） | 远端角色、服务器机关 |
| SoftCorrection | 不回滚，持续本地模拟并向验证态收敛（Correction Rate / Snap 阈值可调） | 碎片、布娃娃 |
| PredictedIfOwned | 本地=Full，远程=Relay | 玩家 pawn |
| PredictedIfOwnedWithSoftFallback | 本地=Full，远程=Soft | 远程副本继续模拟并平滑收敛 |

注意：SoftCorrection 仅 PredictedTransform/Rigidbody(2D)/Projectile3D 支持，不支持者自动（无报错）按 ServerRelay 行为；刚体与 PredictedTransform 同对象时物理组件接管 policy。Scope 组件可按层级批量设策略；`SetPredictionPolicy / SetPredictionPolicyOverride / UsePredictionPolicyScope` 三个运行时 API 语义不同；policy 切换最安全的时机是所有权/阶段边界。

**输入/状态**：
- `INPUT : struct, IPredictedData`；`GetFinalInput`（每 tick）、`UpdateInput`（每 Unity 帧，缓存边沿触发如 jump |= GetKeyDown）、`SanitizeInput`（钳制）、`ModifyExtrapolatedInput`（外推时剥离 jump/fire 等一次性输入，防丢包重放）
- `STATE : struct, IPredictedData<STATE>`（含 IMath 的 Add/Scale/Negate 用于默认插值）；只放影响未来 tick 的数据；`GetUnityState/SetUnityState` 桥接 Transform/Rigidbody；四元数等非线性字段重写 `Interpolate` 用 slerp

**执行流**：每 tick：Pre-Tick → 准备输入 → 存 pre-sim 状态 → Simulate → LateSimulate → 物理通道 → 存 post-sim 状态 → 网络 → PostSim → 推进 tick。回滚（收到验证帧）：丢弃过期帧 → Rollback → 模拟验证 tick → 重放到最新 → SyncTransforms + UpdateInterpolation → onRollbackFinished。时间线只前进或暂停、绝不倒退。

**网络模型**（很有特色）：
- 输入/帧走**不可靠通道**；客户端上传冗余窗口（自适应 input margin，4~32 tick），未变输入每副本仅 1 bit；服务器丢弃完全重复上传；每 20ms 重发当前窗口直到更新窗口替代
- 服务器帧 = 对客户端已验证 baseline 的 **delta** + 每个 identity 最新输入（对客户端上次 ack 的输入块做 delta）；丢帧不重传，下一帧自带缺失 tick 的真实输入重模拟——"丢包代价是重放而非往返"
- **重度丢包恢复**：服务器监测客户端 ack baseline 推进速度，低于半 tick 率时切换该客户端为"可靠全量帧、每 ack 往返一帧"，恢复后自动回到 delta 流；健康连接无论延迟多高都不进入此路径
- DeterministicIdentity 例外：输入走保证送达的 transcript（32 tick 窗口），落后则全量帧重新锚定；用 tick 加盐哈希检测分歧，Desync Policy = Ignore/Report/Resync/Correct

**安全模型**：客户端只能"提议输入"，不能声明位置/血量/命中；SanitizeInput 只是第一层，模拟内仍需服务器校验冷却/弹药/状态/所有权，命中由服务器模拟推导，限制昂贵操作频率；policy 不改变权威（软纠正 ≠ 安全）；模拟回放中禁止直接发 RPC/发奖励/写存档——用 `PredictedEvent` 或 `predictionManager.isVerifiedView` 过滤一次性表现；`PredictedIdentitySpawner` 标记 `[PredictionUnsafe]`，需谨慎使用并依赖网络规则约束。

**内置组件**：PredictedTransform（Graphics 子节点分离视觉与碰撞根，Float Accuracy: Purrfect/Medium/Low）、PredictedRigidbody(2D/3D)（必须在 Simulate 里用包装 API 而非原始 Rigidbody；`onCollisionEnter` 等预测感知事件）、PredictedProjectile3D（球形投射物：重力/触发/反弹）、PredictedIdentitySpawner、PredictedParent（重挂父可回滚、重放、迟到者可见）。

**官方 Best Practices**：
1. 所有可变模拟值进 STATE（含冷却、计数器、随机状态、稳定 PredictedObjectID）
2. Inspector 字段是配置不是状态
3. 模拟必须可重放——禁止音频/粒子/分析/存档/外服调用/每次重放发 RPC
4. 时间与随机用 `delta/PredictedTime/PredictedRandom`，禁用 Time.deltaTime/UnityEngine.Random
5. 服务器校验输入 + ModifyExtrapolatedInput 剥离一次性边沿
6. 选择最便宜的正确的 policy；不要用软纠正掩盖坏的确定性模拟
7. 变长状态用可释放集合、实现 Dispose/IDuplicate&lt;T&gt;；引用存 PredictedObjectID 经 PredictedHierarchy 解析
8. **以远程客户端而非 host 测试**：延迟/抖动/丢包、所有权转移、回滚中 spawn、池复用、不同帧率 tick 率、大纠正与传送、迟到加入

## 五、Plug n' Play 组件

- **NetworkTransform**：位置/旋转/缩放/父级可选同步（No/Local/World），unreliable 通道 + 基于接收端 ack baseline 的 delta 压缩（丢包可恢复）；`ForceSync()`/`ForceSync(player)` 强制全量；Min/Max Buffer 控制插值缓冲
- **Adaptive Sync**（默认开启、零渲染延迟）：控制端每 tick 采样但接收方可精确重建时跳过发送；内置策略支持直线/曲线（转弯、轨道、抛射）/匀角速度旋转，最大间隔 0.3s 强制刷新；自定义策略继承 `NetworkTransformSyncStrategy` 重写 `TryReconstruct`（必须纯函数确定性，两端的策略配置必须一致）；`NetworkTransformCompositeStrategy` 链式组合
- **NetworkRigidbody**：弹簧-阻尼式跟随（Position/Rotation Strength、Correction Range、Hard Snap Distance、Interpolation Delay 0.05s、Prediction Factor）；`TeleportTo(pos, rot)` 清速度、清缓冲、可靠 RPC、弹簧不追逐；`SetSoftParent` 软父级（不改 Unity 层级）；大世界/原点偏移用 `INetworkRigidbodyPositionTransform`（double3 绝对帧传输，必须全端一致配置）
- **NetworkAnimator**：自动同步参数；**Trigger 必须走 `_netAnimator.SetTrigger("Punch")`**
- **NetworkBones**：同步骨骼局部 TRS（布娃娃/IK/jiggle），量化（位置 0.01m/角度 0.5°/缩放 0.05）+ DeltaModule + MTU 分批 + unreliable；spawn 后列表与精度锁定（PurrLock）
- **NetworkReflection**：任意组件字段自动同步（含 Unity 自带组件），Inspector 勾选
- **NetworkStateMachine**：默认 server auth；StateNode/StateNode&lt;T&gt; 挂场景子物体，`machine.Next()/Previous()/SetState(node)`（可带数据 `machine.Next(5)`）；CanEnter/CanExit 条件转移；运行时动态增删状态自动同步
- **NetworkAudioSource**：脏标记位掩码，只发变化字段（volume 变更仅 6 字节）；Play/Stop/clip 走 reliable，volume/pitch 走 unreliable；运行时换 clip 必须注册进 NetworkAssets（否则远端解析为 null）；播放时间只在显式改变时发送，漂移 >0.1s 才对齐

## 六、工具链

- **Conversion Tool**：Roslyn 代码转换（类型/命名空间/特性映射，合并 OnStartServer/OnStartClient → OnSpawned(bool asServer)）+ Prefab 组件替换 + 场景 NetworkManager 迁移；开箱支持 FishNet；可自定义 converter；转换前务必备份
- **PurrLobby V2**：四槽 GameOrchestrator（Session/Lobby/Matchmaking/GameAllocator ScriptableObject），可混搭（如 Nakama 会话+大厅 + PurrTransportGameAllocator 对局）；内置 PurrNet Services/Steam/Nakama 三套预设；LobbyCapabilities 自动隐藏不支持的功能；NakamaGameAllocator 走 WebSocket 中继**只适合回合制**；加载游戏场景时 `NetworkManager.DisableFlags()` 抑制自动启动两帧（游戏场景可保留 auto-start 兼作测试环境）；GameSession 处理离开/GameOverBroadcaster.EndGame()/断线重试三种返回；更新会覆盖 Assets/PurrLobby，自定义应复制到包外
- **PurrChat**：AI 助手；**PurrVoice**：Early Access 语音聊天（网络化音频滤镜，支持 FMOD/WWise）

- **Edgegap**：Addon Library 一键装，需 Docker + Linux Build Support；Build Server → Containerize → Upload → Deploy；支持的 transport 有自动配置复选框（检测 Edgegap 环境变量自动配端口/SSL）
- **Gameye**：零 SDK/插件，纯容器 + REST API；transport 在容器内**固定端口**，Gameye 映射外部端口

## 九、术语表（中英对照）

| 术语 | 解释 |
|---|---|
| Host（主机） | 同机同时跑 server + client；一切带 `asServer` 的回调在 host 上会执行两次（server 侧 + client 侧各一次） |
| Server Auth (Safe)（服务器权威/安全） | 服务器持有真相，强制防作弊路径（同 Mirror/FishNet 默认） |
| Client Auth / Everyone (Unsafe)（客户端权威/人人可用/不安全） | 非 cheat-proof 但非"错误"；适合 Co-op/休闲；Network Rules 设为 unsafe 时任何客户端可直接 spawn/发 RPC |
| Owner Auth（所有者权威） | 拥有者客户端控制该值/组件；无 owner 时 server 自动接管为 controller；适合移动/相机/个人设置，不适合计分/血量等关键值 |
| Controller（控制者） | 对某 identity 最有权限的一方：owner 存在时=owner；无 owner 时=server；非 ownerAuth 场景下永远只有 server 是 controller |
| PlayerID（玩家标识） | 跟踪当前/历史连接的 struct；Cookie 系统下断线重连保持同一 ID 与元数据，便于存档/识别 |
| Channels（通道） | 5 种：ReliableOrdered（默认）、ReliableUnordered、ReliableSequenced（只保最新）、UnreliableSequenced（只保顺序不保到达）、Unreliable（都不保） |
| Early Access（抢先体验） | 暂限付费成员的功能阶段，未来免费开放 |
| MTU（最大传输单元） | 单包上限，由 transport 按通道/连接/平台上报；超限走 Fragment/UpgradeToReliable/Drop 策略 |

## 十、关键结论

1. **设计哲学**：贴近 Unity 原生工作流（Instantiate/Destroy、无烘焙、无 NetworkObject），把权限模型外置到 Network Rules 使开发期 Unsafe → 上线 ServerStrict 无需改代码
2. **带宽优势明显**：RPC 与 NT 基准均大幅低于三大竞品，且官方称尚未优化
3. **PurrDiction 是独立子系统**：不可靠通道 + 输入冗余窗口 + delta 帧 + 丢包重放代替重传 + 自动重度丢包降级全量帧，安全上"客户端只能提议输入"；学习曲线陡峭（官方自己标注 Workflow: Hard），文档要求严格遵守 replay-safe、STATE 全量、确定性时间/随机等纪律
4. **常见坑 Top 5**：模块不能放 List/不能 spawn 后替换；host 双次执行 asServer 回调；Trigger 不走 NetworkAnimator.SetTrigger 会不同步；Adaptive 自定义策略两端不一致；Purr Transport 默认中继禁止生产使用
