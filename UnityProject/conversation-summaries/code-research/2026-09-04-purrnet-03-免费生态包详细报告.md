# PurrNet 官方免费生态包详细报告

> 研究对象：PurrDiction / PurrServices / PurrNetEOSTransport / PurrConversion 四个免费包的源码克隆分析，以及 PurrLobby 的定位确认。

---

## 一、PurrDiction（客户端预测，`dev.purrnet.purrdiction` v1.3.4-beta.3）

**定位与用途**：PurrNet 的 CSP（客户端侧预测）附加包，提供权威服务器 + 客户端预测/回滚/重模拟的完整框架，附带定点数数学库（SoftFloat/FixedPoint）、预测物理（2D/3D）、预测层级/随机/时间等内建系统。MIT 许可（Pebbles Games / Riten SARL）。

**版本与依赖**：包依赖 `com.unity.nuget.mono-cecil 1.11.4`（用于 IL 织入）；隐式强依赖 PurrNet 核心——测试工程锚定 `v1.22.1-beta.5`，asmdef 中 `versionDefines` 对 `dev.purrnet.purrnet` 的 `1.15.0-beta.3` 和 `1.20.0-beta.38` 做特性门控（`PURRSCENE_OBJECT_FILTERS`、`HAS_DISCOVERY_RULE`），说明与核心版本演进深度绑定。

**代码规模**：144 个 .cs、约 25,867 行（含 Examples/Editor/Codegen），是四个包中体量最大者。

**架构与核心实现**：
- **PredictionManager**（`Runtime/Core/PredictionManager.cs`，3419 行，partial 分出 Desync/Visibility 等文件）：继承 PurrNet 核心的 `NetworkIdentity`，按场景单例。`OnEarlySpawn` 中从 `networkManager.tickModule` 取 tickRate 并注册内建系统（`PredictedHierarchy/PredictedPlayers/Predicted3DPhysics/PredictedTime/PredictedRandomSystem`，可用 `BuiltInSystems` 位掩码裁剪）；把 `Physics.simulationMode` 设为 Script 接管物理步进。核心循环挂在核心的 `TickManager.onPreTick/onPostTick` 上：PreTick 依次做 输入准备（服务端 `PrepareInputs` 按本地 tick 消费各客户端输入队列，缺失时按 `_extrapolateMissingInputs` 复用上次输入）→ SaveState（写历史）→ SimulateTick → 物理通道 → LateSimulate → 服务端写帧/发帧，客户端 `FinalizeInputOnClient` 上传输入。PostTick 中客户端 `ProcessQueuedFrames`：逐帧 `RollbackToFrame`（delta 帧，基于 baselineTick）或 `ReadFullFrame` → `SimulateFrame` 存验证态 → `ReplayToLatestTick` 重模拟到本地预测头，并含输入饥饿跳帧、lead 最小/最大钳制（MinLead/TargetLead/AbsoluteMaxLead）等自适应时钟控制。
- **输入冗余**：`FinalizeInputOnClient`（约 1016–1140 行）把 `[ack+1, localTick]` 窗口内 Owned 身份的输入逐 tick 打包，窗口上限 `MaxInputWindow=32`，冗余窗口 `InputRedundancyTicks` 由自适应 lead 控制器的 margin 目标推导（最少 4 tick）；相邻 tick 逐身份做比特级去重（`BitData.Equals` 打 repeat 位）；`InputMtu=960` 字节以上走分片可靠通道；`ResendCachedInput` 每 20ms 定时重发缓存 payload 抗丢包。需要保真输入历史的身份可标记 `requiresGuaranteedInputHistory` 绕过裁剪。
- **PredictedIdentity**（`Runtime/Core/PredictedIdentity.cs` + Module/Lifecycle partial）：所有预测物体的基类（纯 MonoBehaviour），含 `owner`、`PredictedComponentID id`、`predictionPolicy`（FullPrediction/ServerRelay/SoftCorrection 等，可被 `PredictionPolicyScope` 层级覆盖）。抽象方法 `SimulateTick/Rollback/UpdateRollbackInterpolationState`；状态经泛型 `History<T>`（`Runtime/Core/History.cs`，环形缓冲，tick→state）存档。`DeterministicIdentity<STATE>` 用 sfloat 定点状态 + `DesyncPolicy`（哈希上报 `MaybeSendDesyncReport`，服务端 `PredictionManager.Desync.cs` 校验）。状态序列化走 PurrNet 的 `Packer<T>/BitPacker`，服务端验证态缓存 `GetVerifiedHistory<T>`（容量 10 秒 tick）。
- **Codegen**（`Codegen/PredictionProcessor.cs`）：基于 `Unity.CompilationPipeline.ILPostProcessing` + Mono.Cecil 的 IL 后处理器，对所有引用 `PurrNet.Prediction` 的程序集织入（自动实现接口/模块注册类样板），`FPProcessor` 处理定点数。

**与核心的耦合方式**：直接消费 `NetworkIdentity`、`networkManager.tickModule`、`ServerRpc`/RPC、`PurrNet.Packing`（BitPacker/Packer）、`PurrNet.Transports`（分帧发送）、`PurrNet.Pooling/Logging/Utils`、`PlayerID`。属于"同源强耦合"——不是松散适配层，而是共享序列化与 tick 基础设施的官方扩展。

**注意事项**：需 PurrNet ≥1.20（部分特性 1.22）；非确定性物体用 Unity 物理需接受其接管 `fixedDeltaTime`；确定性物体需用其 sfloat/FP 数学；版本升级时注意 versionDefines 门控的特性差异。

## 二、PurrServices（官方后端客户端 SDK，`dev.purrnet.services` v1.1.2）

**定位与用途**：PurrNet 官方托管"认证 + 大厅 + 匹配 + 大厅聊天"后端（默认 `https://purrnet.dev`）的 Unity 客户端 SDK。这是**纯客户端库**，不含服务器代码——服务端是官方运营的 SaaS。MIT。

**版本与依赖**：运行时 asmdef 引用 `PurrNet.Runtime` + `JamesFrowen.SimpleWeb`（WebSocket，随 PurrNet 生态分发）与 `Newtonsoft.Json.dll`。注意：它**不依赖** PurrNet 网络运行时进行通信，HTTP/WS 均为独立通道。

**代码规模**：23 个 .cs、约 4,593 行。

**架构与核心实现**：
- **PurrServices**（`Runtime/PurrServices.cs`）：隐藏单例 MonoBehaviour，`RuntimeInitializeOnLoadMethod` 自动引导，组合 `AuthService` + `LobbyService`，每帧 `Tick()` 驱动所有 `LobbyConnection`。
- **ServiceHttp**（`Runtime/Http/ServiceHttp.cs`）：UnityWebRequest 封装，统一注入头：`Authorization: Bearer <apiKey>`（项目密钥）、`X-Purr-Scope`（环境：`editor`/`production`/自定义）、`X-Purr-Lobby-Compatibility`（取 `Application.version`，实现版本隔离——不同版本客户端互不可见/不可加入）、`X-Player-Session`、`X-Player-Token`。
- **AuthService**：设备匿名登录（provider `system-uuid`，凭 `SystemInfo.deviceUniqueIdentifier`）、用户名密码注册/登录，sessionToken 持久化 PlayerPrefs（Editor 下按项目文件夹隔离）。
- **LobbyService**：REST 全套——`CreateAsync/ListAsync(LobbyQuery 过滤)/JoinAsync/JoinByCodeAsync/QuickJoinAsync/LeaveAsync/DestroyAsync/KickAsync` + 元数据 PATCH，路径 `/api/lobby/*`，返回 `playerToken` 供 WS 鉴权。
- **LobbyConnection**（`Runtime/Services/LobbyConnection.cs`）：基于 SimpleWebClient 的 WebSocket，连上后发 `auth` 消息，服务端回 `authenticated + snapshot`；之后增量事件流：`player_joined/player_left/joinable_changed/metadata_updated/player_metadata_updated/chat/kicked/destroyed`，客户端本地维护 `currentSnapshot`；`ping/pong` 心跳；断线经 `RetryTimer` 指数退避自动重连。
- **配置与分层**（`Runtime/PurrServicesSettings.cs` + Editor 三件套）：密钥/URL 经 PurrNet 的 `ApplicationConstants` 编译进构建；Editor 与 Build 双 profile（编辑器默认 `editor` scope，构建默认 `production`），Editor 可 override 到构建环境。**未关联项目时自动落入免费开发层**（按 `Application.identifier` 命名空间隔离），官方明示"不用于生产，发布前需创建并关联项目"。
- 另含可选 **PurrTelemetry** 遥测模块与运行时调试 GUI（`PurrServicesGUI`）。

**Region 说明**：客户端代码中无 Region/延迟选择逻辑——matchmaking 的区域决策在服务端（本仓库不可见），客户端只透传 scope/query。

**PurrLobby 关系确认**：**PurrLobby 不在本仓库中**。PurrServices 是后端 SDK；PurrLobby（`dev.purrnet.purrlobby`）是独立的前端整包（菜单流 UI + 场景，装入 `Assets/PurrLobby`），经"Provider 架构"（`GameOrchestrator` 上四个 ScriptableObject 槽位：Session/Lobby/Matchmaking/GameAllocator）接入三种后端：PurrNet Services（**依赖本包 PurrServices**，游戏流量走 PurrTransport 中继、以 lobby id 为房间名）、Steam（Steamworks.NET）、Nakama。即 PurrServices 是 PurrLobby 官方后端 provider 的底层依赖。

**注意事项**：sessionToken 明文存 PlayerPrefs；生产使用必须关联项目（暗示商业化层级）；版本号即兼容性门槛，发版需谨慎。

## 三、PurrNet EOS Transport（`dev.purrnet.eostransport` v1.0.1-beta.7）

**定位与用途**：Epic Online Services P2P transport，让 PurrNet 走 EOS 的 NAT 穿透/中继，免自建转发。社区 fork（quentinleon 原作，MIT）官方化重写。

**版本与依赖**：依赖 **PlayEveryWare EOS Plugin**（`com.playeveryware.eos`，提供 EOS SDK 与 `EOSManager`）。asmdef 用 `versionDefines` 在插件存在时定义 `EOS_SDK`，全部 EOS 调用包在 `#if EOS_SDK` 内——插件缺失时编译为空壳且 `isSupported=false`。

**代码规模**：4 个 .cs、约 1,336 行，极精炼。

**架构与核心实现**：
- **EOSTransport**（`Runtime/EOSTransport.cs`）：继承 PurrNet 的 `GenericTransport` 并实现 `ITransport`（onConnected/onDisconnected/onDataReceived/onDataSent/onConnectionState 事件 + listenerState/clientState 双状态机）。`GetMTU` 按通道映射：Unreliable* → `1170-开销`，Reliable* → 分片层最大消息。`measuresRoundTripTime=true` 自实现 RTT。亮点：**host loopback**——对已在 host 的 NetworkManager 调 `StartClient()` 直接短路为进程内队列投递，不过 EOS。
- **EOSServer**（`Runtime/EOSServer.cs`）：`Listen()` 从 `EOSManager.Instance.GetEOSPlatformInterface().GetP2PInterface()` 取 P2P 接口，取 index 0 登录用户为 LocalUserId，`SetPacketQueueSize`（入 4MB/出 2MB，对抗 EOS 默认 64KB 队列瞬时 LimitExceeded），注册三个通知：`AddNotifyPeerConnectionRequest/Established/Closed`；握手包为 1 字节 `0x00`；维护 ProductUserId 字符串 ↔ int connectionId 双向映射；`_lastCleanupTime` 周期清理超时 peer；关闭时释放 notification handle。
- **EOSPeer**（`Runtime/EOSPeer.cs`）：每对端一实例。常量：`EOS_MAX_PACKET=1170`、控制通道 255、HEARTBEAT=1/PING=2/PONG=3；自实现 ping/pong RTT（毫秒时间戳）；`FragmentationLayer` 负责 reliable 大消息分片重组；**背压**：EOS 返回 LimitExceeded 时入托管溢出队列，上限 `MAX_QUEUED_BYTES=32MB`（注释记载了野外 3.5 万缓冲/1.8GB/1fps 的 GC 死亡螺旋教训），超限 Send 失败→上层断开该 peer。

**集成方式**：标准 `GenericTransport` 组件——挂到 NetworkManager、设 `socketName`（双方约定字符串）、客户端设 `remoteProductUserId`（主机 EOS Product User ID）即可。使用前需在 **Tools/EOS Plugin/EOS Configuration** 配好 Epic 产品凭据。

**注意事项**：host 侧连接身份取"第一个登录用户"，多本地用户场景需注意；EOS SDK 未配置时静默不可用，注意检查 `isSupported`。

## 四、PurrConversion（迁移转换工具，`dev.purrnet.conversion` v1.0.0-beta.1）

**定位与用途**：Editor-only 的"配方式"迁移工具，把其他网络库的项目（代码/Prefab/场景三层）转换为 PurrNet。**目前仅内置 FishNet 转换器**；Mirror/NetCode 尚未支持（README 仅称"more converters coming"，仓库中也只有 FishNet Converter 目录），但架构开放可自写。

**版本与依赖**：依赖 PurrNet 核心 + 待迁移源库（Prefab/场景转换需读取源库组件）；自带 Roslyn（`Plugins/` 下 Microsoft.CodeAnalysis.CSharp 等 DLL）做语法树改写。

**代码规模**：11 个 .cs、约 1,679 行（另有 Roslyn DLL）。

**架构与核心实现**：
- **配方三件套**：`NetworkSystemMappings`（纯数据映射表：Namespace/Type/Property/Method/Member/MethodCall/Attribute/AttributeParameter/Parameter/TypeSpecificMember/MemberAccess/TypeNamespaceRequirements + 可覆写的 `SpecialCaseHandler`）、`NetworkPrefabHandling.ConvertPrefab`（换组件抄设置）、`NetworkSceneHandling.ConvertSceneObject`（含 NetworkManager/transport/tickRate 迁移）。`ConverterDiscovery` 反射自动发现同文件夹三件套，免注册。
- **GenericNetworkConverter.ConvertCode**（`ConversionTool.cs`）：Roslyn 管线固定顺序：`ConvertNamespaces→Types→Properties→Members→Attributes→AttributeParameters→SpecialCases→MethodCalls→mappings.SpecialCaseHandler→UsingDirectives`（按 `TypeNamespaceRequirements` 补 using），先做标识符快筛避免全量解析，最后 `NormalizeWhitespace` 落盘；全部改动写入 `ConversionChangelog.txt`。
- **FishNetMappings**：命名空间 `FishNet→PurrNet`；类型 `NetworkConnection→PlayerID`、`NetworkObject→NetworkIdentity`、transport 族（`Tugboat→UDPTransport`、`Yak→LocalTransport`、`FishySteamworks→SteamTransport`、`Multipass→CompositeTransport`）；属性 `IsOwner→isOwner` 等；最精妙的是 `SpecialCaseHandler` 用 SyntaxFactory 把 `OnStartServer/OnStartClient` 两个方法体**合并**为 `protected override void OnSpawned(bool asServer)`，server 版包 `if(asServer)`、client 版包 `else`；`SyncVar` 的 `Value/OnChange/DirtyAll` 经 TypeSpecificMemberMappings 映射为 `value/onChanged/FlushImmediately`。

**注意事项**：Editor-only（asmdef + defineConstraints）；转换前务必备份/提交 VCS；三步（Code→Prefab→Scene）按序独立执行；语义不完全等价处（如 FishNet 双回调语义）需人工复核合并结果。

## 五、免费生态全景总结

| 包 | 性质 | 费用 |
|---|---|---|
| PurrNet 核心 | 网络框架 | **100% 免费**（官方 pricing 页明言永不收费、无抽成） |
| PurrDiction | CSP 预测 | 免费开源（MIT 系） |
| PurrServices 包 | 后端客户端 SDK | 免费；后端有**免费开发层**（未关联项目自动可用），生产需关联项目（服务商业化入口） |
| PurrLobby | 大厅/匹配前端整包 | 免费（含 UI 全流程，依赖 PurrUI；官方后端 provider 依赖 PurrServices） |
| EOS Transport | P2P 传输 | 免费（MIT，fork 官方化） |
| Conversion Tool | 迁移工具 | 免费（目前仅 FishNet） |

**免费部分可覆盖的场景**：从原型到上线的一整条链路——核心网络（RPC/同步/兴趣管理/分层）、高要求动作游戏的客户端预测（PurrDiction）、跨平台 NAT 穿透联机（EOS，免服务器；或 Steam 中继）、大厅/房间码/匹配/聊天（PurrServices 免费层 + PurrLobby 现成菜单流）、以及从 FishNet 迁移（PurrConversion）。**可能付费的点**集中在：PurrServices 生产级托管后端（项目关联后的商业层级，细节不在仓库内）、PurrTransport 游戏流量中继（随 Services 提供）、以及官方 studio 支持服务。

对独立开发者，"PurrNet + PurrDiction + EOS/Steam + PurrLobby(Steam provider)"可组成完全免费且不依赖官方服务器的完整上线方案；愿意依赖官方 SaaS 则用 PurrServices/PurrLobby 的 PurrNet provider 换取零运维。
