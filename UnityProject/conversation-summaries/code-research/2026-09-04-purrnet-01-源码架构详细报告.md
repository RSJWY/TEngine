# PurrNet 源码架构详细报告

> 基于 `dev.purrnet.purrnet` v1.23.0-beta.24 源码克隆分析（package.json），依赖 Mono.Cecil 1.11.4 / Newtonsoft.Json / Collections / Mathematics。

---

## 1. 整体架构与程序集划分

核心位于 `Assets/PurrNet/`，通过 asmdef 划分程序集：

| 目录 | asmdef | 职责 |
|---|---|---|
| Runtime | PurrNet.Runtime | 全部运行时逻辑（Modules、Transports、BitPacker、Components），不依赖 Editor |
| Codegen | PurrNet.Codegen | 基于 Mono.Cecil 的 ILPostProcessor（编译期织入） |
| Editor | PurrNet.Editor | Inspector、设置、Build 处理、PackageManager 等 63 个文件 |
| Addons | Steam/UTP/Nakama/Edgegap/Mathematics | 各为独立 Runtime+Editor 程序集 |
| Externals | LiteNetLib、SimpleWebTransport、7zip、Toolbar-Extender | 第三方库（66 个 .cs） |
| Defaults | 无代码 | NetworkRules / VisibilityRules 预设资产（Unsafe、ServerStrict、ServerOwner 等） |
| Tools | Profiler/DeltaPackerAnalysis | 调试工具 |

依赖方向：Runtime ← Codegen（织入所有引用 PurrNet 的程序集）← Editor。Runtime 下再分 `Managers`（NetworkManager）、`CoreModules`（18 个子系统模块）、`Components`（NetworkIdentity/NetworkModule/NetworkTransform 等）、`BitPacker`（序列化）、`Transports`。

## 2. 核心类与数据流

**NetworkManager**（`Runtime/Managers/NetworkManager.cs`，`sealed partial`，`[DefaultExecutionOrder(-999)]`）：中央枢纽，持有 `GenericTransport _transport`、`NetworkRules`、`NetworkPrefabs`、可见性规则与认证器。关键设计是**双模块集**：`_serverModules` / `_clientModules` 两个 `ModulesCollection`，host 模式下两套并存。`RegisterModules()`（NetworkManager.cs:1170）按依赖顺序装配：BroadcastModule → TickManager → CookiesModule → AuthModule → PlayersManager → PlayersBroadcaster → ScenesModule → ScenePlayersModule → DeltaModule → HierarchyFactory → GlobalOwnershipModule → RPCModule → RpcRequestResponseModule → NetworkTransformFactory 等。

**消息流入调用链**：`ITransport.onDataReceived` → `NetworkManager.OnDataReceived(conn, data, asServer)`（:2370）→ `ModulesCollection.OnDataReceived` → `BroadcastModule`（按 32 位类型 hash 分发，内含 `FragmentationLayer` 分片重组）→ `PlayersBroadcaster.OnRawDataReceived`（Connection→PlayerID 映射后按 `PlayerBroadcastDelegate<T>` 触发）→ `RPCModule.ReceivedUnionBatchedRPC`（解 UnionRPCHeader 为 RPCPacket/ChildRPCPacket/StaticRPCPacket）→ 生成的 `HandleRPCGenerated_N` → 被改名的原始方法 `XXX_Original_N`。流出方向：RPC 发送 → `RPCBatch` 合批 → BroadcastModule 加 5 字节头 → transport.SendToClient/SendToServer。

**NetworkIdentity**（`Components/NetworkIdentity/NetworkIdentity.cs`，partial 拆成 Rules/Modules/LOD/Broadcasting）：挂在每个网络 GameObject 根上，持有 prefabId、componentIndex、网络父子关系（`invertedPathToNearestParent`）、观察者列表、白/黑名单。**NetworkBehaviour 只是个空壳**：`public abstract class NetworkBehaviour : NetworkIdentity {}`——PurrNet 不要求用户继承专用基类，任何 NetworkIdentity 或 `NetworkModule`（可序列化同步类型容器，`Components/NetworkModule/NetworkModule.cs`）都可承载 RPC。`RegisterModuleInternal` 给每个模块分配 byte 级 moduleId（上限 255）。

**PlayerID**（`CoreModules/Players/PlayerID.cs`）：`readonly struct`，内部 `PackedULong _id` + `isBot` 标志，id==0 为 Server。由 PlayersManager + CookiesModule（重连保持 ID）分配。

**ScenesModule**（`CoreModules/Scenes/ScenesModule.cs`，1705 行）：服务器权威的场景 ID 分配（`_nextSceneID`）、buildIndex↔路径 hash 映射、场景操作队列与 `SceneHistory`；配套 `ScenePlayersModule`（玩家↔场景可见性）与 `SceneObjectsModule`。每场景一个 `HierarchyV2`（4314 行）负责 spawn/despawn/观察者/ID 分配（`HierarchyFactory` 为工厂模块）。

## 3. 代码生成（Codegen）

入口 `PostProcessor : ILPostProcessor`（`Codegen/PostProcessor.cs`，5417 行），`Process(ICompiledAssembly)`（:3759）对每个非 Editor、非 Unity 自带的程序集织入。流程：

1. 读取 PE+PDB → AssemblyDefinition（带 AssemblyResolver 处理编译期引用）。
2. 烘焙常量（BakeApplicationConstants/BakePurrVersion）、处理 `IMath<T>` 生成运算符（GenerateAutoMathProcessor）、UnityProxyProcessor。
3. 遍历类型：识别 `NetworkIdentity`/`NetworkModule` 子类，`FindNetworkModules` 收集同步字段并 `CreateSyncVarInitMethod`（:4772）生成 `__XXX_CodeGen_Initialize`，逐字段调用 `RegisterModuleInternal(fieldName, typeName, field, ...)` 完成模块注册（避免反射）。
4. **RPC 织入**：`GetMethodRPCType` 检测 ServerRpc/ObserversRpc/TargetRpc 特性（读取特性 ctor 的 9/11/9 个参数还原 RPCSignature）。对每个 RPC：
   - `HandleRPC`（:2061）：把原方法改名为 `原名_Original_id`，生成同名替身方法——内部构建 RPCSignature、按类型构造 `RPCPacket`（identity）/`ChildRPCPacket`（module）/`StaticRPCPacket`（static），分配 BitPacker，用生成的序列化器写参数，处理 runLocally / requireOwnership 校验 / deltaPacked（多目标时用 `DeltaFanoutGrouper` 分组扇出）/ awaitable（预分配 RpcRequest id）。
   - `HandleRPCReceiver`（:346）：生成 `HandleRPCGenerated_offset+i(BitData packet, RPCInfo info, bool asServer)`——调用 `RPCModule.PostProcessRpc` 解压/解密，再调用 `EmitValidateCall` 做权限校验，最后调原始方法。泛型 RPC 走 `HandleGenericRPCReceiver`（配合 GenericRPCHeader 按类型 hash 还原 Type[] 再 `Packer.Read`）。
   - `GenerateRPCManifestProcessor.EmitRegistration` 生成 `RegisterRPC` 调用，运行时进 `Manifest` 字典（`Runtime/Manifest/Manifest.cs`），供诊断与校验。
5. **序列化器生成**：收集 `usedTypes`（RPC 参数/返回值/字段）∪ `IPackedAuto`/`IPacked`/`IPackedSimple` 实现 ∪ `[RegisterNetworkType]`，交给 `GenerateSerializersProcessor.HandleType` 生成 `{TypeName}_Serializer` 类：静态 `Write(BitPacker, T)` / `Read(BitPacker, ref T)` 逐字段 emit（只写有 packer 的字段），并附带 `[RegisterPackers(priority)]` 的 `Register()` 静态方法（运行时由 `NetworkManager.CallAllRegisters` 反射调用一次，把委托灌进 `Packer<T>`）。`GenerateDeltaSerializersProcessor` 同时生成 `WriteDelta`（返回 bool 表示是否变更）/`ReadDelta`，对值类型/sealed 类型缓存为可内联。最后还生成 `IEquatable`/`IDuplicate` 接口实现（GenerateIEquatableInterface/GenerateIDuplicateInterface）。
6. 写回前做 `RedirectSystemPrivateCoreLibToNetStandard` 与自引用清理，输出新 PE/PDB。

## 4. 序列化系统

**BitPacker**（`Runtime/BitPacker/BitPacker.cs`，884 行）：bit 级读写器。核心状态仅 `byte[] _buffer` + `int _positionInBits`，`positionInBytes = (bits+7)>>3`。支持 `WriteBits(ulong, n)`/`ReadBits(n)`、`AdvanceOneBitAndSet/Clear`（写"有/无"标志位的原语，被生成代码大量使用）。可 `MakeWrapper(ByteData)` 零拷贝包住收到的包。集成 **K4os.LZ4** 的 Pickle（`PickleInto/UnpickleFrom`）用于大消息压缩。有对象池 `BitPackerPool`。整数支持范围压缩：`WriteInteger(data, minValue, maxValue)` 按范围算 bit 数（BitPackerIntegers.cs:24）。

**Packer<T>**（`Packer.cs`）：静态泛型注册表，`DirectWrite/WriteFunc` 委托。区分"精确类型"与"考虑继承"（class 类型写方走 `WriteClass` 处理多态 hash）。原生类型 packer 在 `Packers/` 下手写（PackIntegers/PackStrings(UTF8+长度前缀)/PackUnityTypes(Vector3 按范围压缩)等）；`OptimizedTypes/` 提供 PackedUInt(varint)、Half/HalfVector3、Size 等缩窄类型。用户类型由第 3 节的 Codegen 生成并注册。

**Delta Packer**：两层。手写层 `DeltaPackInteger.cs` 用 **zigzag 差分 + 2bit bucket 选择器**（如 buckets32={4,8,16,32}），先写 1 bit changed 标志；`DeltaPackVectors/Floats` 处理浮点与向量（支持精度分层）。集合层用 **Myers 差分算法**（`Packers/MyersDiff.cs`，经典 forward wavefront + backtrace）产生 `DiffOp<T>`（Add/Delete）操作流，`ListComparator/DictionaryComparator/HashSetComparator` 把 List/Dict/HashSet/Queue/Stack/NativeList 的变更编码为操作序列。`DeltaPacker`（非泛型入口）+ `DeltaPacker<T>`（泛型缓存）提供回退：无注册 delta 时"changed bit + 全量"。

## 5. RPC 系统

三个特性（`CoreModules/RPCs/`）都继承 `PreserveAttribute`，ctor 参数即全部语义：

- **ServerRpcAttribute**（9 参数）：channel、runLocally（本地也执行）、requireOwnership（默认 true，仅 owner 可调）、compressionLevel(LZ4)、asyncTimeoutInSec、stripCode（服务器构建裁剪客户端代码）、deltaPacked、mtuExceeded、immediate（仅限 Unreliable 通道，Codegen 强校验）。
- **ObserversRpcAttribute**（11 参数）：广播给所有观察者，额外 bufferLast（缓冲最后一条给迟到/重连玩家，RPCModule 里 `_bufferedRpcsDatas` 实现）、requireServer（默认 true，仅服务器可发起）、excludeOwner、excludeSender。bufferLast 与 deltaPacked 互斥。
- **TargetRpcAttribute**（9 参数）：服务器→指定玩家，首个参数若为 PlayerID 类型被 Codegen 识别为 SenderId 特殊参数。

**Static RPC**：不继承 NetworkIdentity 也能用（Codegen 报错则要求 static），走 StaticRPCPacket + `Hasher.GetStableHashU32(类型名)` 寻址。

**Generic RPC**：生成代码在发送端把每个泛型实参类型的 stable hash 写入流；接收端 `GenericRPCHeader.SaveReadHash` → `Hasher.ResolveType(hash)` 还原 Type[]，再经非泛型 `Packer.Read(stream, type, ref object)` 反序列化，最后 `MethodBase.Invoke` 或构建的 closed-generic 调用。

**Awaitable RPC**（`RpcRequestResponseModule.cs`）：RPC 方法返回 `Task`/`Task<T>`（或 UniTask，条件编译 `UNITASK_PURRNET_SUPPORT`）。发送端生成代码预分配递增 requestId，挂 `TaskRequestCompleter(T)`（内部 TaskCompletionSource）；RPC 体内 `return new RpcResponse(...)` 时服务器向请求方回写响应包；接收端 `EmitRequestIdParsing` 解出 id 完成对应 TCS。带 `asyncTimeoutInSec` 超时。ObserversRPC 禁止返回 Task（多目标无法回传）。

**合批**：`RPCBatch` 把同玩家的多个 RPC 打成 `RPCBatchPacket`（count+BitData），配合 `UnionRPCHeader` 三合一去重包头；MTU 超限行为可全局/RPC 级配置（UpgradeToReliable/Drop/Fragment）。

## 6. SyncType 系统

同步类型是普通 C# 可序列化类，继承 `NetworkModule`（不是 MonoBehaviour），以 `[SerializeField]` 字段挂在 NetworkIdentity 里，由 Codegen 的 `__CodeGen_Initialize` 注册。家族在 `Components/NetworkModule/`：SyncVar、SyncList、SyncDictionary、SyncHashset、SyncQueue、SyncArray、SyncEvent、SyncTimer、SyncBigData、SyncAsset、SyncLazyRef、ValidatedSyncVar 等。

**SyncVar<T>**（SyncVar.cs）：setter 里 `PurrEquality<T>` 比较，不等则权限检查（`isControllingSyncVar` = parent.IsController(ownerAuth)，非控制端写会 LogError 并拒绝）→ `SetDirty()` → 订阅 TickManager。**发送策略**（OnTick，:241）：脏后首次用可靠通道（`ForceSendReliable`→SendToAllReliably(++_id, value)），后续用不可靠（`ForceSendUnreliable`），停止脏后再补一次可靠确保终态——`_id` 单调递增供接收端丢旧。`sendIntervalInSeconds` 限频。`OnObserverAdded` 时 `SendLatestState` 全量补发；ownerAuth 变更/重连有对应处理。序列化即生成代码为 `SendToAll/SendToServer` 这类隐式广播方法生成 delta 编码调用（WriteDelta 带 `_id` 版本）。

**SyncList<T>**（SyncList.cs）：包装 `List<T>` + `_pendingChanges` 队列，每个变更记为 `SyncListChange<T>`（Added/Removed/Insert/Set/Cleared + index），tick 时把 pending 操作流发出（即操作级增量），接收端重放并触发 `onChanged`。同样支持 ownerAuth/ownerOnly/interval。SyncDictionary/Hashset/Queue/Stack 同理（配合第 4 节的 Comparator）。

## 7. Authority / Ownership 模型

**NetworkRules**（`Components/NetworkBehaviour/NetworkRules.cs`，ScriptableObject）是策略中心，分结构化子规则：`SpawnRules`（spawnAuth/despawnAuth/defaultOwner/propagateOwnershipByDefault/despawnIfOwnerDisconnects）、`OwnershipRules`（assignAuth=ConnectionAuth.Server 默认、transferAuth=Owner|Server、removeAuth、overrideWhenPropagating）、`RpcRules`（可放宽 ignoreRequireServerAttribute 等）、`VisibilityRules`、`NetworkSceneRules`、`NetworkTransformRules`、`HostMigrationRules`。权限检查入口如 `NetworkRules.HasDespawnAuthority(identity, player, asServer)`。

**运行时归属**：`GlobalOwnershipModule`（`CoreModules/Ownership/`）按场景维护 `SceneOwnership`，批量广播 `OwnershipChange/OwnershipChangeBatch` 包；身份层 `NetworkIdentity.GiveOwnership(PlayerID, silent, propagateToChildren)`（NetworkIdentity.cs:1082）/`RemoveOwnership`（:1219），客户端转移需过 transferAuth。核心判定 `isController`（:274）：`isSpawned && (hasConnectedOwner ? isOwner : isServer)`——ownerAuth 的 SyncType/行为在 owner 在线时由 owner 主导，否则回落服务器。断线时按 `despawnIfOwnerDisconnects` 处理，模块收到 `OnOwnerDisconnected`。支持 host 迁移（IPromoteToServerModule / ITransferToNewServer 接口贯穿各模块）。

## 8. Transports

接口分层（`Runtime/Transports/Interface/ITransport.cs`）：`IListener`（Listen/StopListening）+ `IConnectable`（Connect/Disconnect）合成 **ITransport**，事件 onConnected/onDisconnected/onDataReceived/onDataSent/onConnectionState；数据模型 `ByteData`（data/offset/length 只读结构体）；`Channel` 四通道（ReliableUnordered/UnreliableSequenced/ReliableOrdered/Unreliable）；默认方法含 GetMTU、GetRoundTripTime、FlushConnection、keep-alive。**GenericTransport**（MonoBehaviour 抽象桥，`transport => ITransport`）负责查找 NetworkManager、在 Start/Stop 前后注册/注销模块，并提供 async `Ping()` 探测（不成为 player）。

内置实现：**UDPTransport**（封装 LiteNetLib，支持 NetworkSimulation 模拟延迟/丢包与 Edgegap 云配置）、**WebTransport**（封装 SimpleWebTransport，WebSocket/WebGL）、**LocalTransport**（同进程回环）、**CompositeTransport**（多 transport 聚合，如同机直连+远程 UDP）。Addons：**SteamTransport**（P2P）、**UTPTransport**（Unity Transport Package）、**NakamaTransport**（中继/匹配）、Edgegap 集成。`FragmentationLayer`（790 行）提供不可靠通道的分片重组（带 budget/超时淘汰）。

## 10. Examples 目录

仓库根 `Assets/Examples/`（PurrNet.Examples 程序集）：**Top Down Shooter**（最全示例：PlayerMovement/Shoot/Health/NetworkAnimator 相关、WheelSpawning、可见性白名单测试、异步 RPC 测试）、**Box carry**（物体搬运/归属转移）、**Animation**、**AddressablesTest**、**RandomShapes**、**NetworkRigidbodyTest**、**NetworkAudioSourceTest**、**NetworkTransformFilterTest**、**ColliderRollback**（回滚碰撞体射击验证）、**TestingDeltas**（大数据 delta 压测）、**SceneLoading**、**Spawning**、**Sumo**、**AutoStartUI**（启动模式选择 UI）、**Template**（最小可用模板：Rules+Prefabs+Scene）。另 `Assets/PurrNet/Examples/` 内有内部示例程序集（PurrNet.Internal.Examples）与 Minimal 场景。

---

**总结**：PurrNet 是"服务器权威 + 细粒度 authority 可配"的框架，三大特色：(1) 全量 Mono.Cecil 织入——RPC 收发两端、序列化器、delta 序列化器、模块注册全部编译期生成，运行时零反射热路径；(2) 比特级序列化 + zigzag/bucket 整数差分 + Myers 集合 diff 的多层 delta 压缩，且 RPC 与 SyncType 共用同一套 packer；(3) 模块化 NetworkManager（server/client 双模块集、场景隔离的 HierarchyV2），配合 NetworkRules 资产把 spawn/ownership/RPC/visibility 权限做成数据配置。
