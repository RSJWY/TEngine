## 1. 执行摘要

PurrNet 是一款 **100% 免费（MIT）、服务器权威、高度模块化** 的 Unity 高层网络库，主打"网络逻辑贴近 Unity 原生工作流"：

- **`Instantiate()` / `Destroy()` 即网络生成/销毁**——由 IL 编译期织入（Mono.Cecil）自动生成全部 RPC 收发、序列化器、模块注册代码，运行时热路径零反射
- **无烘焙、无 NetworkObject**：每个 NetworkBehaviour 本身就是 NetworkIdentity，支持组件级所有权；场景 ID 运行时按层级计算，无版本控制冲突
- **Network Rules**：权限模型（谁能 spawn/转移所有权/调 RPC）外置为 ScriptableObject 配置，开发期用 Unsafe 快速迭代，上线切 ServerStrict **无需改一行代码**
- **带宽性能显著优于竞品**：RPC 基准比 FishNet 低 49%、比 Mirror/NetCode 低 ~74%；NetworkTransform 基准比 FishNet 低 49%、比 Mirror 低 61%、比 NetCode 低 73%（且官方称尚未做主动优化）
- **PurrDiction**（独立免费包）提供完整的回滚式客户端预测 + 可选确定性定点数模拟，网络模型设计相当先进（不可靠通道 + 输入冗余窗口 + delta 帧 + 丢包重放代替重传）

**一句话定位**：设计哲学介于 Mirror（易用）与 FishNet（性能/功能）之间且兼取两家之长，特色是"编译期代码生成 + 权限外置配置 + 免费 + 现代化 API（泛型/静态/awaitable RPC）"。

## 3. 源码架构分析

### 3.1 程序集划分

```
Assets/PurrNet/
├── Runtime/    → PurrNet.Runtime      全部运行时逻辑（Managers/CoreModules/Components/BitPacker/Transports）
├── Codegen/    → PurrNet.Codegen      Mono.Cecil ILPostProcessor（PostProcessor.cs 单文件 5,417 行）
├── Editor/     → PurrNet.Editor       Inspector/构建处理/设置（63 文件）
├── Addons/     → Steam/UTP/Nakama/Edgegap/Mathematics 各自独立程序集
├── Defaults/   → NetworkRules/VisibilityRules 预设资产（Unsafe/ServerStrict/ServerOwner）
├── Externals/  → LiteNetLib、SimpleWebTransport、7zip、K4os.LZ4 等
└── Tools/      → 带宽 Profiler 等调试工具
```

**代码规模**：核心 487 个 .cs / 约 95,300 行（Runtime 378 文件 69,287 行；Codegen 22 文件 8,581 行）。主要命名空间：`PurrNet`(182)、`PurrNet.Packing`(75)、`PurrNet.Modules`(75)。

### 3.2 核心类与数据流

**NetworkManager**（`Runtime/Managers/NetworkManager.cs`，sealed partial，`[DefaultExecutionOrder(-999)]`）：
- 持有 `GenericTransport`、`NetworkRules`、`NetworkPrefabs`、可见性规则、认证器
- **双模块集设计**：`_serverModules` / `_clientModules` 两套 `ModulesCollection`，host 模式下并存
- `RegisterModules()` 按依赖顺序装配 18 个核心模块：BroadcastModule → TickManager → CookiesModule → AuthModule → PlayersManager → PlayersBroadcaster → ScenesModule → ScenePlayersModule → DeltaModule → HierarchyFactory → GlobalOwnershipModule → RPCModule → RpcRequestResponseModule → NetworkTransformFactory 等

**消息流调用链**：
```
流入: ITransport.onDataReceived → NetworkManager.OnDataReceived → BroadcastModule（32位类型hash分发 + FragmentationLayer分片重组）→ PlayersBroadcaster（Connection→PlayerID）→ RPCModule.ReceivedUnionBatchedRPC → 生成的 HandleRPCGenerated_N → 原始方法(改名 XXX_Original_N)
流出: RPC调用 → RPCBatch 合批 → BroadcastModule 加 5 字节头 → transport.SendToClient/SendToServer
```

**其他关键类**：
- `NetworkIdentity`：挂在网络 GameObject 根上，含 prefabId、观察者列表、网络父子路径、白/黑名单；**NetworkBehaviour 只是空壳**（`NetworkBehaviour : NetworkIdentity`）——不要求用户继承专用基类
- `NetworkModule`：非 MonoBehaviour 的可序列化同步类型容器（SyncVar 等的基类），可嵌套，byte 级 moduleId（上限 255）
- `PlayerID`：readonly struct，id==0 为 Server，配合 CookiesModule 断线重连保持 ID
- `ScenesModule`（1,705 行）+ 每场景一个 `HierarchyV2`（4,314 行）：服务器权威场景 ID 分配、spawn/despawn/观察者管理

### 3.3 代码生成（Codegen）——核心竞争力

`PostProcessor : ILPostProcessor` 对每个引用 PurrNet 的程序集织入：

1. **模块注册**：扫描 NetworkIdentity/NetworkModule 子类的同步字段，生成 `__XXX_CodeGen_Initialize`，逐字段调用 `RegisterModuleInternal(fieldName, ...)`——避免反射
2. **RPC 织入**：
   - 原方法改名 `原名_Original_id`，生成同名替身：构建 RPCSignature → 构造 RPCPacket/ChildRPCPacket/StaticRPCPacket → 用生成的序列化器写参数 → 处理 runLocally / requireOwnership / deltaPacked / awaitable
   - 接收端生成 `HandleRPCGenerated_N(BitData, RPCInfo, asServer)`：解压/解密 → 权限校验 → 调原始方法
3. **序列化器生成**：为所有用到的类型生成 `{TypeName}_Serializer` 类（静态 `Write/WriteDelta/Read/ReadDelta`），通过 `[RegisterPackers]` 生成的 `Register()` 灌入 `Packer<T>` 委托表
4. 附带生成 `IEquatable`/`IDuplicate` 接口实现、`IMath<T>` 运算符

### 3.4 序列化系统（BitPacker）

- **BitPacker**（884 行）：bit 级读写器，`WriteBits/ReadBits`、`AdvanceOneBitAndSet`（"有/无"标志原语）、零拷贝 wrapper、K4os.LZ4 压缩、对象池
- **整数范围压缩**：`WriteInteger(data, min, max)` 按范围算 bit 数
- **Delta Packer 双层**：
  - 值层：zigzag 差分 + 2bit bucket 选择器（buckets32={4,8,16,32}）
  - 集合层：**Myers 差分算法**产生 Add/Delete 操作流，覆盖 List/Dict/HashSet/Queue/Stack
- 用户类型四级序列化方案：`IPackedAuto`（全自动）→ `IPackedSimple` → `IPacked` → 静态扩展方法（最高性能）
- 优化类型：PackedUInt(varint)、Half 精度浮点/向量等

### 3.5 RPC 系统

三个 Attribute（均支持泛型/静态/awaitable 组合）：

| Attribute | 关键参数 |
|---|---|
| `[ServerRpc]` | requireOwnership(默认true)、runLocally、channel、compressionLevel(LZ4)、stripCode(服务器构建裁剪)、deltaPacked、immediate、asyncTimeoutInSec |
| `[ObserversRpc]` | requireServer(默认true)、bufferLast(迟到/重连玩家补发)、excludeOwner、excludeSender |
| `[TargetRpc]` | 首参 PlayerID 为目标；bufferLast |

- **Static RPC**：不依赖 NetworkIdentity，按类型名 stable hash 寻址
- **Generic RPC**：发送端写泛型实参类型 hash，接收端 `Hasher.ResolveType` 还原 Type[] 再反序列化调用
- **Awaitable RPC**：返回 `Task<T>`（支持 UniTask），自动 TaskCompletionSource 配对 requestId；ObserversRpc 禁止返回 Task
- **`RPCInfo info = default`** 参数获取 `info.sender`
- **MTU 策略**：全局/RPC 级 `mtuExceeded` = Fragment(默认) / UpgradeToReliable / Drop
- **本地执行**：`PurrCompilerFlags.EnterLocalExecution()` 局部绕网

### 3.6 SyncType 系统

以 `[SerializeField] NetworkModule` 字段挂在 Identity 上（**禁止 `List<SyncVar>`、禁止 spawn 后替换实例**）：

- **SyncVar&lt;T&gt;**：`new(5, ownerAuth:true, ownerOnly:true)`；变更检测 → 权限检查 → 脏标记；发送策略为"脏后首帧可靠、后续不可靠、停止脏后补一次可靠确保终态"，`_id` 单调递增供接收端丢旧；新观察者加入全量补发
- **ValidatedSyncVar**：客户端预测立即生效（validated=false），服务器 multicast 验证通过广播（validated=true），拒绝则回滚；packetId 忽略过期 ack
- **SyncList/Dictionary/Hashset/Queue/Array**：操作级增量（Added/Removed/Insert/Set/Cleared），接收端重放并触发 onChanged
- **SyncLazyRef&lt;T&gt;**：懒解析 NetworkIdentity 引用（目标未加载时等待，出现自动解析）
- **SyncEvent**：`Invoke(10)` 自动网络广播，Inspector 可配置
- **SyncTimer**：自动对账（默认 3s），可手动驱动
- **SyncInput&lt;T&gt;**：owner 发输入 server 跑逻辑，自动去重，支持模拟 host ping 保证公平
- **ownerOnly: true**：数据只发 owner+server（真服务端过滤）；转移所有权自动补发
- **SyncBigData**：字节数组 + KB/s 限速，异步分片，断线续传

### 3.7 Authority / Ownership 模型

**NetworkRules**（ScriptableObject）结构化子规则：

- `SpawnRules`：spawnAuth / despawnAuth / defaultOwner / propagateOwnershipByDefault / despawnIfOwnerDisconnects
- `OwnershipRules`：assignAuth(Server默认) / transferAuth(Owner|Server) / removeAuth
- `RpcRules`：可放宽 ignoreRequireServerAttribute 等
- 另有 VisibilityRules / NetworkSceneRules / NetworkTransformRules / HostMigrationRules

**运行时**：`NetworkIdentity.GiveOwnership(PlayerID, silent, propagateToChildren)` / `RemoveOwnership`；核心判定 `isController = isSpawned && (hasConnectedOwner ? isOwner : isServer)`——owner 在线时 owner 主导，否则回落 server。断线按 `despawnIfOwnerDisconnects` 处理。支持 host 迁移（IPromoteToServerModule 接口贯穿各模块）。

### 3.8 Transports

接口分层：`IListener` + `IConnectable` → **ITransport**（onConnected/onDisconnected/onDataReceived/onDataSent/onConnectionState + GetMTU/GetRoundTripTime/FlushConnection）。`GenericTransport`(MonoBehaviour 抽象桥) 负责挂接 NetworkManager、async Ping 探测。

| Transport | 实现 | 要点 |
|---|---|---|
| UDP（默认） | LiteNetLib | 支持延迟/丢包模拟、Edgegap 云配置 |
| Web | SimpleWebTransport | WebSocket/WebGL，支持 SSL |
| Local | 同进程回环 | 单机复用网络代码 |
| Composite | 多 transport 聚合 | **跨平台联机**（Web+Steam+EOS 同服） |
| Steam（Addon） | Steamworks.NET | P2P |
| UTP（Addon） | Unity Transport Package | |
| Nakama（Addon） | 中继/匹配 | |
| Purr Transport | 官方免费中继 | 6 区域；**默认地址仅限开发，生产需自建** |
| EOS（免费包） | PlayEveryWare EOS 插件 | 见 §5.3 |

通道模型 5 种：ReliableOrdered（默认）/ ReliableUnordered / ReliableSequenced / UnreliableSequenced / Unreliable。`FragmentationLayer`（790 行）提供不可靠通道分片重组。

## 4. PurrDiction 客户端预测（免费独立包，v1.3.4-beta.3）

**规模**：144 .cs / ~25,867 行，MIT。依赖 PurrNet ≥1.20（asmdef versionDefines 门控特性），含定点数数学库（SoftFloat）。

### 4.1 架构

- **PredictionManager**（3,419 行，继承 NetworkIdentity，按场景单例）：接管 `Physics.simulationMode = Script`，核心循环挂 `tickModule.onPreTick/onPostTick`
- **服务端**：PreTick 顺序 = 输入准备（缺失按配置外推复用上次输入）→ SaveState → SimulateTick → 物理通道 → LateSimulate → 写帧/发帧
- **客户端**：PostTick 处理收到的验证帧 → Rollback（delta 帧）→ 重放至本地预测头（含输入饥饿跳帧、MinLead/TargetLead/AbsoluteMaxLead 自适应时钟钳制）
- **PredictedIdentity**：所有预测物体基类（纯 MonoBehaviour），抽象 `SimulateTick/Rollback/UpdateRollbackInterpolationState`，状态经环形缓冲 `History<T>` 存档
- **DeterministicIdentity&lt;STATE&gt;**：sfloat 定点状态 + tick 加盐哈希检测分歧，DesyncPolicy = Ignore/Report/Resync/Correct

### 4.2 网络模型（先进设计）

- 输入/帧走**不可靠通道**；客户端上传冗余窗口（自适应 4~32 tick），相邻 tick 比特级去重（未变输入仅 1 bit），每 20ms 重发当前窗口
- 服务器帧 = 对客户端已验证 baseline 的 **delta** + 每个 identity 最新输入；**丢帧不重传**——下一帧自带缺失 tick 真实输入重模拟，"丢包代价是重放而非往返"
- **重度丢包自动降级**：监测 ack baseline 推进低于半 tick 率时切"可靠全量帧、每 ack 往返一帧"，恢复后自动回 delta 流
- 确定性身份例外：输入走保证送达的 transcript（32 tick 窗口）

### 4.3 预测策略（只影响客户端，服务器永远全模拟）

| 策略 | 行为 | 适用 |
|---|---|---|
| FullPrediction | 本地超前模拟+回滚重放 | 本地玩家、关键物理 |
| ServerRelay | 只跑已验证 tick（刚体变 kinematic） | 远端角色、服务器机关 |
| SoftCorrection | 不回滚，持续模拟向验证态收敛 | 碎片、布娃娃 |
| PredictedIfOwned(WithSoftFallback) | 本地=Full，远程=Relay/Soft | 玩家 pawn |

### 4.4 安全模型与纪律

- 客户端只能**提议输入**，不能声明位置/血量/命中；命中由服务器模拟推导；模拟回放中禁止直接发 RPC/发奖励（用 `PredictedEvent` 或 `isVerifiedView` 过滤）
- **STATE 纪律**：所有影响未来 tick 的可变值（含冷却/计数器/随机状态）必须进 STATE；时间/随机用 `PredictedTime/PredictedRandom`，禁用 `Time.deltaTime/UnityEngine.Random`
- 内置组件：PredictedTransform（视觉子节点分离）、PredictedRigidbody 2D/3D（包装 API + 预测感知事件）、PredictedProjectile3D、PredictedIdentitySpawner（标记 `[PredictionUnsafe]`）、PredictedParent
- **测试要求**：以远程客户端而非 host 测试（延迟/抖动/丢包、所有权转移、回滚中 spawn、池复用、不同帧率 tick 率、大纠正与传送、迟到加入）

## 5. 免费生态包详解

### 5.1 PurrServices（官方托管后端 SDK，v1.1.2，23 .cs / ~4,593 行）

纯客户端 SDK（服务端是官方 SaaS，默认 `https://purrnet.dev`）：

- **AuthService**：设备匿名登录（system-uuid）/ 用户名密码，sessionToken 持久化
- **LobbyService**：REST 全套（Create/List/Join/JoinByCode/QuickJoin/Leave/Destroy/Kick + 元数据 PATCH）
- **LobbyConnection**：WebSocket 增量事件流（player_joined/chat/kicked 等）+ 指数退避重连
- 版本隔离：`X-Purr-Lobby-Compatibility = Application.version`，不同版本互不可见
- 双 profile（editor/production scope）；**未关联项目自动落入免费开发层（不用于生产）**

### 5.2 PurrLobby（免费前端整包）

独立包（不在 PurrServices 仓库），装入 `Assets/PurrLobby`。**GameOrchestrator 四槽位**（Session/Lobby/Matchmaking/GameAllocator ScriptableObject）可混搭，内置三套 provider 预设：PurrNet Services（依赖 PurrServices，游戏流量走 PurrTransport 中继以 lobby id 为房间名）、Steam（Steamworks.NET）、Nakama（WebSocket 中继，只适合回合制）。更新会覆盖目录，自定义应复制到包外。

### 5.3 EOS Transport（v1.0.1-beta.7，4 .cs / ~1,336 行）

- 依赖 PlayEveryWare EOS 插件（`com.playeveryware.eos`），`versionDefines` 条件编译——插件缺失时空壳
- `EOSTransport : GenericTransport, ITransport`；`EOSServer` 用 EOS P2P 接口 + 三通知注册；`EOSPeer` 自实现 ping/pong RTT、心跳、分片
- 工程细节扎实：包队列 4MB/2MB（对抗 EOS 默认 64KB 瞬时 LimitExceeded）、32MB 托管溢出队列背压（注释记载野外 1.8GB 缓冲 GC 死亡螺旋教训）、host loopback 短路（StartClient 进程内投递不过 EOS）
- 使用：挂 NetworkManager、双方约定 socketName、客户端设主机 ProductUserId

### 5.4 PurrConversion（v1.0.0-beta.1，11 .cs / ~1,679 行）

- **目前仅内置 FishNet 转换器**（Mirror/NetCode 未支持），架构开放可自写
- 三层转换：Roslyn 代码管线（Namespace→Type→Property→Member→Attribute→MethodCall 固定顺序）+ Prefab 组件替换 + 场景 NetworkManager 迁移
- 映射示例：`Tugboat→UDPTransport`、`NetworkObject→NetworkIdentity`、`NetworkConnection→PlayerID`；精妙处：`OnStartServer/OnStartClient` 方法体自动合并为 `OnSpawned(bool asServer)`（server 版包 `if(asServer)`、client 版包 `else`）
- 全部改动写入 `ConversionChangelog.txt`；**转换前务必备份**

### 6.2 兼容性

PC/Linux/Mac/Android/iOS/WebGL/Switch/PS/Xbox/专用服务器全部支持。PurrDiction 支持 Unity 2022 与 Unity 6；PurrLobby 要求 2022.3+。

### 6.3 Plug n' Play 组件亮点

- **NetworkTransform + Adaptive Sync**（默认开启、零渲染延迟）：接收方可精确重建时跳过发送；内置直线/曲线/匀角速度策略，最大 0.3s 强制刷新；自定义策略继承 `NetworkTransformSyncStrategy`（**两端配置必须一致**）
- **NetworkRigidbody**：弹簧-阻尼跟随；`TeleportTo` 清速度清缓冲；`SetSoftParent` 软父级
- **NetworkAnimator**：Trigger **必须**走 `_netAnimator.SetTrigger("Punch")`（直接调 Animator 不同步）
- **NetworkBones**：骨骼 TRS 量化（0.01m/0.5°/0.05）+ MTU 分批；spawn 后列表锁定
- **NetworkReflection**：任意组件字段 Inspector 勾选自动同步
- **NetworkStateMachine**：StateNode 挂场景子物体，`machine.Next(data)` 条件转移自动同步
- **NetworkAudioSource**：脏标记位掩码，volume 变更仅 6 字节；运行时换 clip 必须注册进 NetworkAssets
- **Collider Rollback**（延迟补偿）：不物理移动 collider 而是"弯曲射线"求解命中，避免意外物理事件

### 6.4 术语表

| 术语 | 解释 |
|---|---|
| Host | 同机 server+client；**一切 `asServer` 回调在 host 执行两次** |
| Server Auth (Safe) | 服务器持有真相，防作弊路径 |
| Everyone (Unsafe) | 人人可执行；适合 Co-op/开发期；经 Network Rules 切换 |
| Owner Auth | 所有者控制；无 owner 时 server 接管为 controller |
| Controller | owner 存在时=owner，否则=server |
| PlayerID | 玩家标识 struct；Cookie 系统断线重连保持同 ID |
| Channels | 5 种（见 §3.8） |

### 6.5 常见坑 Top 5（官方文档明确警告）

1. NetworkModule 禁止放 List/动态创建、禁止 spawn 后替换实例
2. Host 上 `asServer` 回调双次执行
3. Trigger 不走 `NetworkAnimator.SetTrigger` 不同步
4. Adaptive Sync 自定义策略两端不一致
5. Purr Transport 默认中继禁止生产使用

### 6.6 其他工具链

- **Code Stripping**：客户端构建自动剥除服务器代码（`[ServerOnly(StripCodeModeOverride)]`）
- **Bandwidth Profiler**：逐 RPC 参数检查、丢失分片统计
- **延迟模拟**：内置 UDP 模拟（release 需 `SIMULATE_NETWORK` 宏）；全进程推荐 Clumsy
- **托管**：Edgegap（Addon 一键装 + Docker）/ Gameye（纯容器+REST）
- **集成**：UniTask（awaitable RPC 条件编译 `UNITASK_PURRNET_SUPPORT`）、Dissonance 语音、Cozy Weather

## 7. 综合评估

### 优势

1. **真免费无套路**：MIT、无 CCU/收入分成，核心功能全部免费
2. **带宽效率领先**：两大基准均大幅低于 FishNet/Mirror/NetCode
3. **开发体验好**：Instantiate/Destroy 原生 API、无烘焙、权限外置可后期收紧、泛型/静态/awaitable RPC 现代 API
4. **技术底子扎实**：全量编译期织入零反射、bit 级序列化 + 多层 delta 压缩、PurrDiction 的"丢包重放代替重传"网络模型设计先进
5. **生态完整**：免费部分可覆盖 原型→上线 全链路（核心+预测+EOS/Steam P2P+大厅匹配+FishNet 迁移）
6. **迭代极活跃**：核心 492 个 release

### 风险/注意

1. **仍处 beta**（1.23.0-beta.24），dev 分支常有 breaking change；release 分支较稳
2. **PurrDiction 学习曲线陡峭**（官方自标 Workflow: Hard），需严格遵守 STATE/确定性纪律
3. 社区规模（656 star / 3k Discord）小于 Mirror/FishNet，遇坑主要靠 Discord 官方支持
4. PurrServices 免费层仅限开发；PurrTransport 中继生产需自建或付费
5. 转换工具仅支持 FishNet（从 Mirror/NetCode 迁移需手动）

### 与竞品对比一句话

| | PurrNet | FishNet | Mirror | NetCode |
|---|---|---|---|---|
| 费用 | 免费 MIT | 免费核心+付费 Pro | 免费 MIT | 免费 |
| 权威模型 | Rules 外置可切换 | Server 为主 | Server 为主 | Server 为主 |
| 客户端预测 | PurrDiction（免费独立包） | 内置（Pro 版更强） | 无内置（需 CSP 插件） | 内置 |
| 烘焙 | 无 | 无 | 场景 ID 需注意 | 有（生成器） |
| API 风格 | Instantiate 原生+织入 | NetworkObject.Spawn | NetworkServer.Spawn | RPC/NetworkObject |
| 带宽 | 最优 | 次之 | 较高 | 较高 |

## 8. 对 TEngine 集成的初步建议

（结合本仓库 tengine-purrnet 分支背景）

1. **安装**：Package Manager Git URL `https://github.com/PurrNet/PurrNet.git?path=/Assets/PurrNet#release`（或 OpenUPM `dev.purrnet.purrnet`）
2. **起步**：场景挂 NetworkManager + UDPTransport，Rules 先用 `Unsafe` 预设快速跑通，上线前切 `ServerStrict`
3. **与 TEngine 流程结合点**：Instantiate/Destroy 原生语义与 TEngine 对象池需确认兼容（PurrNet 自带池化开关，`OnPoolReset` 还原 SyncType）；SceneModule 服务器权威加载与 TEngine 场景流程（Procedure）需要对齐；GameMode 层可用 NetworkStateMachine/NetworkRules 表达权限
4. **客户端预测**：动作类玩法建议 PurrDiction，但注意其接管 Physics.simulationMode 与 tick 驱动方式，需验证与 TEngine 的 Update/FixedUpdate 流程不冲突
5. **验证顺序建议**：先跑 Examples（Top Down Shooter 最全），再做最小集成 Demo（Template 场景），最后引入 PurrDiction
